# 冰壶 AI 训练路线总说明

> 这是一份给项目成员看的总说明。只读这一篇，就应能理解：我们为什么不用“直接大训 PPO”，本地模拟器、搜索和模型各自做什么，模型具体怎么学，以及接下来按什么顺序推进。
>
> 当前范围：**严格本地 PhysX 模拟器、非扫冰、单 end 优先**。扫冰和多 end 都是后续阶段，不能混入当前结论。

## 一、我们最终想做成什么

我们要的不是一个只会在固定参数表里挑名字的机器人，而是一个能根据局面决定出手的冰壶 AI。

它在一手球前需要回答三件事：

1. 这手该打什么思路：守壶、进营、清壶，还是保守扔掉？
2. 这手的力度、瞄准和旋转该是多少？
3. 当前局势下该追求稳定，还是值得冒险搏更高分？

目前一手非扫冰动作写成：

```text
(v0, h0, w0)
```

- `v0`：力度；
- `h0`：左右瞄准；
- `w0`：旋转。

之后扫冰验证完成，才把扫冰操作作为额外动作加入；现在不把它偷偷混进训练或成绩里。

## 二、四个角色分别做什么

### 1. 严格本地模拟器：负责“把球算出来”

本地 PhysX 模拟器接收一组出手参数和当前场面，按照当前已复刻的非扫冰物理推到所有壶停止。它会受到摩擦随机性的影响，所以同一组参数可以用不同随机序列重复试验。

它只回答事实问题：

> “这组参数在这条随机序列下，最后发生了什么？”

模拟器本身不判断战术好坏，也不替我们选择动作。

### 2. 战术库：负责“先给几个有意义的起点”

当前已有左/右守壶、中路进营、清壶、扔出界等基础战术。每种战术都有一个默认参数，例如左守壶可从 `(2.7, -1.0, 0.0)` 开始。

这叫“固定战术参数”。它不是说模拟器没有参数，而是说不搜索时，直接采用预先写好的数值或简单公式。清壶会根据目标壶左右位置调整瞄准，但仍是预先写好的规则。

战术库的角色只是提供起点，**不是最终动作空间**。

### 3. 搜索老师：负责“多试几种球，再选更好的”

搜索从战术库给出的起点出发，在附近细调 `(v0, h0, w0)`，并让每个候选球在多条随机摩擦序列下重复模拟。

它不只看“理论上最高分”的一球，还看：

- 平均能得几分；
- 翻车概率多大；
- 在当前是领先还是落后的局势下，风险是否值得承担。

因此搜索老师给出的不是一句“选 B”，而是一份完整答案：候选有哪些、各自试了多少次、均值和波动多大、最后选哪组连续参数、终局得分可能如何分布。

### 4. 策略价值模型：负责“快速缩小搜索范围”

模型看一眼局面后，不直接替代严格模拟器。它负责快速提出少量值得搜索的方向，并预测局面大概会走向什么结果。

这样严格搜索不用从整个连续空间乱试，只需在模型指出的少数区域细调。

```text
模型负责快
搜索负责选
模拟器负责算准
```

## 三、第一阶段：先验证搜索老师，不急着训练模型

在让模型学习前，必须先证明老师真的比固定战术强。

### 要比较的两种出手方式

```text
基线：按规则直接用固定战术参数出手
老师：从同样的战术起点出发，在附近连续试球后再选
```

比较要求：

- 使用预先固定的代表性局面：空场、守壶、单碰撞、双碰撞、最后一壶；
- 固定每个方法的总模拟预算；
- 搜索用过的随机序列不能拿来给自己打分；
- 用另一批独立随机序列复测；
- 有 hammer 和无 hammer 分开报结果；
- 报平均 end 分、得分分布和不确定性，不能只挑最好看的个例。

P0.1 当前只从一 end 的最后五手开始：每个候选球都能让固定的后续策略继续打到真实 end 结束。这样不会把“一壶后的临时 house 局面”错当成最终得分。

只有连续搜索在独立复测中稳定赢过固定战术，才进入下一阶段。

## 四、第二阶段：模型究竟怎么学习

这一阶段模型的参数更新方式是**监督学习**，不是一开始就用 PPO。

### 一条训练样本包含什么

```text
输入：
  全部壶的位置（严格回放保留朝向 yaw）
  第几壶、还剩几壶
  当前是谁出手、谁有最后一壶
  当前场上暂时谁得分、得几分
  多 end 时再加入总分差和剩余 end

搜索老师答案：
  各候选战术/连续区域的搜索权重
  最后选中的 (v0, h0, w0)
  每个候选的样本数、均值、波动和风险下界
  本 end 最终 -8 到 +8 分各自的概率
```

### 模型学习哪三件事

1. **优先试什么。**

   例如老师认为进营、守壶、清壶的可取程度分别是 60%、30%、10%，模型学习输出相近的优先级，而不是只背一个唯一答案。

2. **参数该往哪里调。**

   模型不只说“进营”，还学习从“进营默认参数”往哪个方向调整力度、瞄准和旋转。

3. **局面最后大概怎样。**

   模型学习预测 end 得分的概率分布，例如 +1 分、+2 分各有多大概率；这比只报一个平均分更能区分稳球和搏分球。

### 参数如何实际更新

每次取一小批搜索老师样本：

```text
模型先预测
→ 与老师的候选权重、出手参数、得分分布比较
→ 算出三类误差
→ 用反向传播把网络内部参数往“误差更小”的方向调一点
→ 换下一批样本，反复进行
```

实际损失由三部分组成：

```text
战术/候选权重预测误差
+ 连续参数预测误差
+ 得分概率预测误差
```

模型起步建议是共享“看场面”的部分，再根据是否拥有 hammer 分成两个策略输出头。这样既共享壶位关系，又不强迫先手和后手用同一打法。

## 五、这算不算强化学习

算，但不是“每一局结束后直接用 PPO 按输赢改网络”的那种第一步做法。

```text
内层：搜索老师给出明确答案，模型用监督学习拟合答案。
外层：模型参与提出候选，候选在模拟器里得到结果，搜索据此产生更好的答案，再反过来训练模型。
```

外层的答案不是人工写死的，而是模型自己试球、得到得分反馈后不断变好的，因此这是搜索驱动的强化学习／近似策略迭代。

我们暂不把 PPO 当主线，原因不是 PPO 不存在，而是当前问题中：

- 一局长，前面一壶的好坏很晚才知道；
- 物理随机性和碰撞使单局奖励噪声很大；
- 连续动作区域里好球很稀少；
- 对手同时变化，训练分布不稳定；
- 严格模拟有成本。

直接 PPO 需要很多对局才能分清一壶是好是坏；搜索老师能在每个局面给出更密集、更具体的学习信号。

PPO 后续可以作为补充：当搜索蒸馏已经得到可靠基础策略、并且有稳定对手池和整局评测后，再用它微调整场博弈目标。不是当前 P0/P1 的前置条件。

## 六、第三阶段：模型变强后如何继续变强

模型学到第一版后，会参与生成下一轮数据，但仍不能自己给自己判卷：

```text
随机或预设一个局面
→ 当前模型先提出少量候选球
→ 严格搜索在候选附近复核、扩展并细调
→ 搜索得到较可靠的最终选择和得分分布
→ 保存成新的训练样本
→ 用监督学习训练下一版模型
```

模型变强的作用是让搜索把预算集中在更可能成功的区域；搜索仍负责纠正模型的错误。只有“模型候选 + 同预算搜索”优于“纯搜索”，才说明模型真的帮到了搜索。

## 七、第四阶段：不能只和最新自己打

如果新模型只和“刚训练出来的自己”对局，它很可能只会克制当前版本，换一个风格就失效。

因此对手池至少包含：

- 基础脚本；
- 队友 PPO；
- 历史模型检查点；
- 小预算搜索模型；
- 当前候选模型。

训练和验收都从中随机抽对手。历史数据也不能只保留最近几局，要保留一部分旧局面，防止模型忘掉旧打法。

新模型不能因为偶然赢了最新版自己就直接替换旧模型；它必须在固定对手池中，分别作为有 hammer 和无 hammer 的一方，通过预先设定的胜率、平均得分和稳定性门槛。

## 八、第五阶段：从单 end 走向整场比赛

单 end 时，先优化本 end 最终能得几分。

多 end 时，目标会改变：落后两分且只剩最后一壶时，稳定拿一分仍可能输；这时一颗成功率低但可能拿三分的球，反而可能更正确。

因此后续会用“剩余 end 数、当前总分差、下一 end 的 hammer 情况”建立胜率表，把模型预测的 end 得分分布换算成整场胜率。最后一壶会单独提高搜索预算。

## 九、当前不做什么

1. **不把扫冰加入当前训练结论。** 扫冰需要单独验证协议触发时间、摩擦变化和碰撞后行为。
2. **不直接跑完整 16 手深树搜索。** 当前先验证根节点连续搜索；没有可靠价值模型前，过早截断会误判局面。
3. **不把队友 PPO 当老师。** 它是有价值的对手和基线，但不是严格搜索生成的真值标签。
4. **不把论文中的样本数照抄成标准。** 1,600 次搜索在不同论文中含义不同，最终以本机成本和独立测试提升决定预算。
5. **不只报混合胜率。** 有/无 hammer 必须拆开；模拟器版本、是否扫冰、对手池和样本量必须写清楚。

## 十、阶段总览与验收门槛

| 阶段 | 产物 | 能进入下一阶段的条件 |
| --- | --- | --- |
| P0：验证搜索老师 | 固定局面上的“固定战术 vs 连续搜索”报告 | 连续搜索在独立随机序列复测中稳定更好，且分 hammer 报告。 |
| P1：搜索数据与第一版模型 | 完整训练数据、策略价值模型 | 模型能在未见局面上接近老师；模型候选能让同预算搜索更快或更强。 |
| P2：稳定自对弈 | 对手池、历史样本、模型晋级机制 | 新模型对固定对手池整体提升，不只赢最新自己。 |
| P3：多 end 与最后一壶 | 胜率表、最后一壶专用搜索 | 在领先/落后测试局面上提高预期整场胜率。 |
| P4：扫冰 | 经逐 tick 验证的扫冰模型与策略 | 与 Unity/比赛协议验证通过后，才加入正式训练。 |

## 十一、一句话版

**先用严格模拟器把球算准；再用搜索从很多球里挑准；然后让模型学会快速提出值得搜索的球；最后让模型在不同对手和整场比赛目标下持续改进。**
