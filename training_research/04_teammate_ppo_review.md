# 队友 PPO 版本审查与对手接入

## 来源与定位

原始交付包已解压至 `research_archive/teammate_ppo_deploy/`，未改动其训练代码或权重。

这不是“PPO 直接输出连续投壶参数”的模型，而是：

```text
116 维局面特征
  → PPO 在 13 个离散战术中选一个
  → 手写 strategy_library 把战术转成 BESTSHOT(v0, h0, w0)
```

因此它是一个混合体：PPO 学“什么时候用哪种战术”，手写库负责“这类战术具体怎么投”。

## 结构核对

| 项目 | 实际内容 |
| --- | --- |
| 观测 | 116 维：16 颗壶各 5 个特征（位置、距圆心、我方/对方、是否在营）+ 壶次/局势/击打/战术上下文。 |
| 动作 | 13 个离散战术：占位、进营、防守、击打、打甩、传击、粘球、清壶、双飞等。 |
| 动作参数 | 不由网络预测；由 `strategy_library.py` 和 `data.json` 的手写规则/标定表生成。 |
| 网络 | `116 → 256 → 128 → {13 类 policy, 1 个 value}`，Tanh MLP。 |
| 权重 | `latest.pt`，PPO checkpoint 第 10 次更新；已安全只读检查，张量尺寸与代码完全匹配。 |
| 奖励 | `0.9 × 局面塑形奖励 + 0.1 × end 最终得分`，另有击打奖惩与一手后的延迟布局奖励。 |
| 扫冰 | PPO 路径默认关闭扫冰。 |

## 优点

- 战术库覆盖面比当前最小策略树大：有 takeout、hit-roll、freeze、double-hit、push-in 等。
- 网络只做 13 选 1，推理很快；空场合法动作会落到 `occupy`，而不是盲目挑击打。
- 有动作合法性 mask，无法生成的手写战术不会直接被执行。
- 观测包含先后手、壶次、局面特征，适合作为一个有固定风格的自对弈对手。
- 默认不扫冰，和当前非扫冰训练范围一致。

## 局限与风险

- 它没有在连续 `(v0, h0, w0)` 空间学习；最终精度完全受手写战术参数约束。
- 训练奖励主要是人工局面评价，而不是严格模拟器下的完整终局得分分布；可能偏好“看起来占优”的布局。
- checkpoint 只有第 10 次更新，包内没有训练曲线、对手构成、样本量或正式评测结果，强度尚未证明。
- 当前入口只支持 Unity socket 协议，不提供 `act(state)` 形式的本地模拟器接口。
- 它的 `strategy_library` 带有旧标定表；必须在严格模拟器上单独验收各战术的落点和碰撞效果，不能直接视为严格物理最优。

## 作为博弈对手的建议

### 先做：基线对手

把它列为 `teammate_ppo_v1`，用于衡量我们的搜索蒸馏策略是否学会击败一个“会选战术、但不会连续微调”的固定对手。

评测必须：

- 先手、后手各跑相同数量；
- 同时报告胜率、平均得分和得分分布；
- 固定它的 deterministic 推理；
- 保留原版本权重，不允许被新模型覆盖。

### 本地适配器：已完成纯推理层

适配器在 `training_research/opponents/teammate_ppo_adapter.py`。它直接使用 PyTorch 和原始 `latest.pt`，没有转换权重，也没有改动队友代码；对外暴露：

```python
opponent.choose(position, player_is_init, shot_num, ...) -> PPOOpponentDecision
```

其中 `PPOOpponentDecision.bestshot` 即原策略库生成的 `(v0, h0, w0)`。

已用 3 个代表局面，将适配器与原 `PPOTacticsRobot` 的选中战术和 `BESTSHOT` 逐项比对，结果完全一致。回归测试在：

```text
training_research/opponents/test_teammate_ppo_adapter.py
```

下一步是给严格模拟器的 CPython 3.8 环境安装 PyTorch，并将这个纯推理适配器接入一局完整的交换先后手评测。它不需要 Unity socket。

## 当前结论

**值得作为对手池中的一个基线，但不应作为我们的训练标签或“真值策略”。**

它最有价值的地方是丰富的手写战术库和固定打法；我们的连续搜索老师应在它给出的候选附近继续优化，而不是退回只选 13 类固定战术。
