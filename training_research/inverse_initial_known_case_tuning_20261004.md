## 本地已知解的范围

扫描当前加速模拟器的 37061 条原始正向记录，并读取已有严格搜索成功证据。每组出手必须在同一物理冰面、同一目标下有至少三个不同种子的实际成功记录；核查首次接触和目标壶间真实碰撞，不能只看两壶被移出。重复编码和筛选副本不重复计数。

按冰面和目标对去重后，得到 27 个冰面、22 个布局组、69 组参照出手。当前原方法在 10 秒/128 次上限内解出 27/27，额外五种子全部通过 23/27；成功耗时中位数 0.308 秒，最大 3.674 秒。

再根据已采到的终态，给未被原目标约束的初始壶及出手壶补充终态要求：存活壶用 0.15 米区域，移除壶用 `OUT_OF_PLAY`，原有目标要求保留。新目标也必须有三个实际成功种子的记录支持；不满足的证据不作为已知解。得到 26 个冰面、21 个布局组，原方法在单独测试中解出 26/26，最大耗时 6.226 秒。

两组大部分是同一冰面上的不同目标，不能相加宣称有 53 个独立冰面；也不是未经开发使用的盲测。成功出手与种子只存于单独的 `references.json`，不进入在线求解的 `scenes.json`；求解器不读取测试答案。

## 观察到的问题与调法

“已知可解局面初值普遍离解很远”没有得到这次测试支持。一个较慢局面，评估到的初值为 `(5.0,-0.11832,5.0)`，已知成功参照为 `(5.127,-0.10052,5.30153)`，横向只差 0.0178 米，但原搜索仍用了 101 次模拟。参照解不唯一，参数距离只是在有限已知出手中的距离，不能证明某个收敛区域。

试验一：保守搜索先横向、再速度、再旋转，小步长 `(0.12,0.06,0.8)`，找到改善就继续，且提前留预算给其他路线。26 局交错对照中，原方法 26/26，试验方法 24/26，额外五种子全部通过分别为 22/26、17/26。这一方案不作为默认。

试验二：保留原 MADS 方向、步长和阶段分配，只在两个原始迭代入口各试六个轴向邻居，步长分别为速度参数 `±0.12`、横向 `±0.03`、旋转参数 `±0.4`。完整通过三个种子就返回，否则以已观察损失更低的邻居作为该入口，继续原迭代。仍受共同时间和总调用数限制；六个邻居是六个动作候选，不等于固定六次模拟，候选通过导航种子后还需要继续复验。

26 个有终态约束局面的同条件交错结果：

| 指标 | 原方法 | 初值轴向微调 |
| --- | --- | --- |
| 三个搜索种子全部通过 | 26/26 | 26/26 |
| 额外五种子全部通过 | 21/26 | 21/26 |
| 搜索模拟总次数 | 553 | 380 |
| 成功耗时中位数 | 0.613 秒 | 0.533 秒 |
| 需要迭代的请求耗时中位数 | 1.903 秒 | 1.380 秒 |
| 最慢成功请求 | 6.095 秒 | 2.991 秒 |

模拟总调用数减少 31.3%；部分局面仍变慢。例如两个局面分别从 36/34 次变为 55/48 次，因此不宣称逐局加速。两种方法交错运行并固定自身主线程 CPU4；实际频率只观测，不锁定。原生模拟预热不计入搜索，几何路径缓存懒加载，第一份几何请求可能支付冷缓存成本；整体耗时改善不能全部归于微调。模拟调用数及后面慢局的变化提供另一项证据。

## 原有四十局回测与默认选择

完整回测原有两批 40 个冰面，原方法和微调方法都解出同样的 23 局，没有新增或丢失的解，原来 17 局仍未找到。额外五种子全部通过的局数分别为 19/40、18/40。

成功耗时中位数为 0.436/0.376 秒，但最慢成功请求为 3.891/5.389 秒；搜索模拟总次数为 2473/2435。在这一组上，收益不如终态约束组明显，也没有证明随机输入下更稳。因此默认保留原方法，微调明确作为可选项，不据此宣传整体成功率提高或普遍更快。

十秒是启动下一次模拟前检查的预算，已启动的一次允许结束。本轮最大超时分别为 72.1/51.8 毫秒，不能理解成强制中断 PhysX 的硬实时保证。已有的同输入跨复用终态差异仍未定位；本次没有利用猜测修改物理。

在线使用：

```python
from training_research.inverse_initials import BudgetedDoubleSolver

solver = BudgetedDoubleSolver()  # 重复使用，构造成本不计入后续预算
result = solver.solve(scene)  # 默认 10 秒，原方法
trial = solver.solve(scene, initial_polish=True)  # 可选初值微调，仍为 10 秒
```

仅 `success=True` 的 `shot` 可以作为验收通过的动作；失败记录中的最佳尝试仍只用于诊断。这些都是有限种子下的观测，尚不支持任意冰面、任意随机状态都成功的结论。

最终 API 另做了一次无 benchmark 预热的检查：同一较慢终态目标，构造后首次默认调用在 10.064 秒/107 次模拟后未找到，随后显式开启微调的调用在 1.971 秒/22 次模拟后找到三种子通过的解。两次共用环境且缓存与输入历史不同，不能作为严格同条件的耗时对照，也不能据此将差异归于某一个原因。它同时说明，前面的 26/26 是对应预热测试中的有限观测，不能推广为每次冷启动都必定成功。
