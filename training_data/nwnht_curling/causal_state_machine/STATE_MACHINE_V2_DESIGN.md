# 先手战术状态机 v2：先构造状态，再验证边

## 结论

当前 v1 只能把棋盘稳定映射到一个**粗盘面索引**，不能称为已验证的
战术状态机，也不能从中推出“这条边大概率赢”。v2 的任务顺序必须是：

```text
棋盘坐标 + 先手第 K 壶
  -> 可解释的分层状态 S
  -> 可执行目标局面族 G（不是出手后的效果标签）
  -> S -- G --> S' 的观察证据与终局结果
  -> 通过留出局与反驳门，才成为候选策略边
  -> 最后才由 PhysX 判断当前目标约束是否能反解
```

最后一步的 PhysX 不参与状态定义，也不用于把历史相关性说成胜率证明。

## 为什么不能只聚类先手获胜局

“先手最终获胜”只能作为边的结果标签，不能先用它筛掉样本再定义状态。
只保留胜局会造成选择偏差：失败时常见的盘面被删除，同一盘面下的失败转移
也不再可见，因而无法比较哪一个目标局面更好。

因此：

- **状态空间和状态同态检验：**使用全部有效先手记录；
- **边的结果统计：**保留 `first_end_margin`、先手本局是否得分等终局标签；
- **离线混杂审查：**可使用队伍、赛事等变量，但它们绝不进入运行时状态；
- **运行时：**仍只读 `K + 壶的颜色和坐标`。

在不使用比分、局号和整场赛况的前提下，系统可定义、可验证的目标是
“当前 end 的先手局部结果”，例如提高先手 end margin 或先手得分概率；它
**不能**诚实地证明优化了整场比赛胜率。整场胜率需要比分和局数等被明确排除
的决策上下文。

## v1 保留什么，缺什么

v1 的 `CORE` 使用：控分方、双方营内壶数、双方中线/侧翼守壶数；`FINE`
另含可见壶数和一个保护代理。这些特征有三个正确用途：

1. 作为 v2 的第一级粗分；
2. 提供高支持样本的入口；
3. 明确“后方壶被同色守壶遮住”只是几何代理，不是安全声明。

但同一 v1 `CORE` 内依然会混入显著不同的战术局面，例如：前/后营的差异、
左右对称还是同侧堆叠、中心线通道是否拥挤、守壶是否真正在目标与来壶方向
之间、两颗敌壶是否有可绑定的双飞组合。故 v1 不能直接作为策略节点。

## v2 的运行时状态

令状态为 `S = (K, C, H, G, R)`；所有量均由当前坐标计算，均采用“先手方 /
对手方”相对颜色，不依赖队名。

| 层 | 内容 | 用途 |
| --- | --- | --- |
| `K` | 先手本 end 第 1--8 壶 | 决定行动时序；绝不与不同 K 合并。 |
| `C` | 空营 / 先手控分 / 对手控分 / 距按钮近似平手或不确定；附双方最近壶的深度桶 | 分清最基本的得分压力。 |
| `H` | 双方在 `button`、前营左/右、后营左/右的占位直方图（每格 `0/1/2+`） | 不再只记录“营内总数”。 |
| `G` | 双方中线、左翼、右翼守壶的数量与深度桶（`0/1/2+`） | 区分中线和普通守壶，不能把两者混成“有守壶”。 |
| `R` | 关系特征：同色守壶对营内壶的遮挡、目标壶前方通道占用、敌方营内壶可组成的单清/双清候选、左右镜像规范化标记 | 表达战术关系而非只数壶。 |

这里的“通道/遮挡/组合”只是从坐标计算的**盘面关系特征**，不是 PhysX
可达性结论，更不是“安全壳”结论。任意候选碰撞路线仍可能在最后阶段被反击。

### 左右镜像规范化

冰壶棋盘在左右方向近似对称。对每一盘面同时计算原始表示和 `x -> -x` 的镜像
表示，按确定性字典序取其一为状态键，并在运行时保存镜像位。这样同一套策略
可在需要时把目标区域镜像回真实坐标，减少人为把“左侧版”和“右侧版”分成
两套样本。

不对前后镜像：来壶方向使前/后并不对称。

## “两个棋盘是同一状态”的可证伪定义

不是坐标很接近就算同一状态，而是在相同 `K` 下先满足相同分层特征，再通过
留出比赛的经验同态检验。对一个候选状态单元，比较其细分子类的：

1. 历史可辨认目标局面族 `G` 的分布；
2. 在给定 `G` 后，己方出手后状态 `U` 的分布；
3. 对手回应后的下一个先手状态 `S'` 分布；
4. end 终局标签的分布。

若训练集和按 `match_id` 隔离的保留集都显示某个几何细节使上述分布稳定改变，
则原状态必须**分裂**；若支持度足够且变化在预登记阈值内，才暂时允许合并。
支持不足的单元不假装等价，标为 `SEARCH_REQUIRED` / `INSUFFICIENT_EVIDENCE`。

这给的是可复查的“预测同态”证据，不是数学上的完全 Markov 证明。

## 边不再写成“实现了某效果”

一条部署候选边的形式应为：

```text
E = (S, G, U_target, S'_distribution, outcome_evidence, fallbacks)
```

其中 `G` 是可在出手前表达的 `GoalState` 约束族，例如：

- 指定当前角色绑定的 1--2 颗对方营内壶必须出界；
- 出手壶最终必须进入按钮/前营左侧等有半径的区域；
- 双方某些区域的占位数必须满足上下界；
- 不满足前一目标时可切换的第二、第三目标约束。

历史记录中无法唯一反推新增壶或被清壶身份的碰撞样本，必须标为
`ABSTAIN` 或仅保留为占位级模板；不能伪造精确落点。现有
`extract_anonymous_goal_templates.py` 的保守身份限制应继续保留。

`ADD_OWN_HOUSE_LAYER`、`GAIN_OWN_SCORING_CONTROL` 等只能是观察到的
`S -> U` 结果/中介标签，可用来描述边是否成功，不能作为运行时动作。

## “这条边导向胜利”的证据门

对每一条边必须区分以下等级；系统只能在最终通过的等级上提高声明强度。

| 等级 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| `HISTORICAL_TEMPLATE` | 这种目标形态在历史中出现过，且有多少支持。 | 人类意图、因果收益、可执行性。 |
| `OBSERVATION_STABLE` | 在隔离比赛中其 `U/S'` 分布没有明显漂移。 | 相比其他目标更能赢。 |
| `CAUSAL_CANDIDATE` | 使用预先冻结的状态、目标、混杂控制和 OPE/敏感性检验后，留出集仍支持相对优势。 | 绝对胜率保证；未测混杂不存在。 |
| `EXPERIMENTALLY_VALIDATED` | 对可执行 `G` 的随机化/受控本地对局试验，在固定对手集合及预算下优于基线。 | 真实顶尖赛事的普适胜率。 |

现有 NWNHT 观察壶谱的两条处理定义都没有通过隔离保留集门，因此当前所有边
最高只能是 `HISTORICAL_TEMPLATE` 或 `OBSERVATION_STABLE`，不得发布成
`CAUSAL_CANDIDATE`。这不是代码问题，而是证据不足。

## 实施顺序

1. 固定 v2 特征字典、镜像规范和状态 ID；对全量有效 records 重建状态。
2. 在按比赛隔离的开发/保留划分中做状态分裂/合并检验，输出状态目录和每类
   支持度；不根据胜负筛样本。
3. 用 `S -> U -> 对手回应 -> S' -> end label` 的连续记录提取 `GoalState`
   目标族边，边保留观察频率、成功率、对手回复和终局结果，但不声称因果。
4. 对高支持、可运行时绑定的边，预注册比较集与因果门；旧的投后效果代理和
   叫球文本代理均不复用为部署动作。
5. 只有边通过独立留出验证或新的受控干预证据后，才进入策略候选表。
6. 此时才调用 PhysX：它只报告“当前预算下已找到 / 未找到解”，失败切换到
   同一策略边的回退目标；不能把“未找到”写成物理无解，也不能反过来证明该
   边能赢。
