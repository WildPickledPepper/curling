# 阶段 1：先手因果逐手转移数据审计

## 结论

NWNHT 本地 SQLite 可以构造先手所需的三段逐手链：

```text
S_K（我方投前） → U_K（我方投后） → S_(K+1)（对方回应后）
```

对手的叫球与评分也被单独保存，因此后续可以把对手回应建模为 `B_K`，而不是把它混到我方动作效果里。

这只证明了**数据库快照链完整且可追溯**；不证明上游视觉坐标完全无误，也不构成任何因果或战术结论。

## 产物

- `artifacts/nwnht_first_player_causal_transitions_v0.jsonl`
  - 86,984 行；每行是一颗先手壶；
  - 包含 `s_before_own`、`u_after_own`、`s_after_opponent_reply`；
  - 包含双方上游叫球/评分、仅本 end 的终局标签与离线赛事元数据；
  - 不含整场胜负或比分作为状态特征。
- `artifacts/nwnht_first_player_causal_transitions_v0_manifest.json`
  - 接受/拒绝原因、源库和 50 个待人工复核 end ID。
- `artifacts/nwnht_first_player_causal_transitions_v0_quality.json`
  - 自动完整性检查和每个 K 的行数。

构建器：[build_first_player_causal_transitions.py](build_first_player_causal_transitions.py)。它以只读方式打开上游 SQLite，并拒绝覆盖既有输出。

## 运行时/离线边界

运行时未来只允许使用：`own_throw_number` 和当前壶面坐标。

以下字段仅允许用于离线因果校正、数据分组或终局标签，禁止进入策略状态：队伍、赛事名/日期、投球评分、end 得分、end 结果。
