# 先手八步状态图：43 个候选簇的壶形解释

> 状态：**探索历史档案，不作为当前部署状态机。** 它解释的是平面 k-means 旧版 43 簇。当前应使用 `artifacts/nwnht_first_player_macro_state_graph_v1_supported.json` 与 `FIRST_PLAYER_MACRO_STATE_V1_FINDINGS.md`：后者用可解释宏观壶形、最低样本支持度和 PhysX 回退替代了未收敛的微观簇数。

结论：这些簇主要在区分三类信息：营内的控制权、守壶/中线屏障、以及壶面拥挤程度。它们不是策略命令，更不是胜率排序。

这里的“当前占分”仅指**此刻**哪一方营内壶更靠近按钮及连续占了几颗，是壶面几何特征；它不是比赛比分，也没有进入本状态图的上下文变量。

每一个名称是根据簇的均值特征和 JSON 中的 medoid 代表壶面做出的中文概括。NWNHT 存在重叠壶漏检可能，故“多壶”“受保护”等均为候选形态，不可直接拿来做 PhysX 终局证明。`n` 为历史样本数。

## 使用边界

这些标签只回答“这簇大致是什么壶形”，不回答“此时该打什么”。一个可执行节点还必须补上：本方战术目标、对手回应分支、失败回退，以及本地 PhysX 对具体目标的可达与合法验证。

此外，K2–K8 当前都达到 6 簇上限；相邻簇是否该继续细分或合并，尚需跨比赛稳定性检验。尤其样本少于 500 的 `K2_C04`、`K5_C02`、`K5_C06`，只能先作为候选簇，不宜直接做部署规则。
