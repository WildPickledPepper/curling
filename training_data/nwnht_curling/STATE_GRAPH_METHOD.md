# NWNHT 离散状态图：第一版方法

结论：第一版先让 NWNHT 的四人赛全量逐投数据决定“有哪些重复局面”，而不是把现有 P1–P8 直接当成数据结论。输出的是候选状态图，不是能赢的策略树，也不替代 PhysX。

## 样本边界

- 主数据：`external_research/NWNHT_curling/curling-main/src/world_curling_ss.db`；只读。
- 默认只纳入 `Mens_Teams`、`Womens_Teams`、`Mixed_Teams`，不把混双的预置壶/10 投规则混入当前八壶四人赛模型。
- 每局必须有 0–16 共 17 个壶面帧，16 手投手严格交替，且红黄两色能由“上一手到本手新增一颗保留壶”反推到两队、无冲突。达不到就剔除，不做猜测。
- 公开库的壶位是自动检测，可能漏掉重叠壶。因此它只支持宏观战术模式和状态转移统计，不能支持毫米级碰撞、守壶绝对安全或具体 `v/h/w` 结论。

## 一条样本是什么

每个样本是一条：

`本手前壶面 S_t → 上游记录的叫球 A_t → 下一手前壶面 S_(t+1) → 本局/比赛结果`

坐标永远从该局首手方视角表达：`first` 是第 1 手投壶的队，`opponent` 是后手队。这样同一张图可直接截取 `FIRST_TO_THROW_*` 节点给先手策略使用，也保留对手回应节点。

## 特征和聚类

状态不直接使用按序排列的 16 颗原始坐标，而用可审计的壶面结构：

- 首手/后手可见壶数、营内壶、普通守壶、中线守壶、中线营内壶、近似被本方守壶遮住的营内壶；
- 双方在“守壶、营内前部、按钮、营内后部 × 左/中/右”的计数；
- 当前暂得分方/数、双方最近营内距离；
- 本局前比分差、局号和精确手数；
- 硬上下文：轮到首手还是后手；1–5（FGZ）、6–10（布局）、11–14（收束）、15–16（末手）。

每一个“角色 × 手数阶段”内部标准化后做 k-means。为避免在同一全量数据上把 `k=1..6` 重复拟合多次，最多抽取跨时间均匀分布的 2,500 条来用 BIC 选择 `k` 和初始中心；随后**所有**合格样本都会回填到选定中心、进行全量重分配和中心重算，节点样本数、动作频数和转移边均来自全量数据。默认每分区最多 6 簇、每簇至少 250 条。状态名例如 `FIRST_TO_THROW_FGZ_1_5_C02` 是中性编号，不含“安全”“进攻”等未经验证的判断。

边记录为 `from + observed_action + to + count`。`observed_action` 是数据库叫球的归并标签（DRAW、GUARD、TAKEOUT、RAISE 等），表示历史上发生过什么，不表示模型推荐什么。

注意：首个 `nwnht_four_player_state_graph_v0.json` 是加入“精确手数”特征前的诊断产物，只按四个大阶段分区。加入该特征后的全量结果为 `nwnht_four_player_state_graph_v1_exact_shot.json`。两者都可用于验证数据链和观察转移，均不能直接作为最终节点定义；仍需用下述留出比赛准则决定粒度。

## 如何运行

```powershell
python training_data\nwnht_curling\discover_state_graph.py
```

默认会新建 `training_data/nwnht_curling/artifacts/nwnht_four_player_state_graph_v1_exact_shot.json`，若文件已存在会拒绝覆盖。快速结构检查可加 `--limit-ends 300` 并指定一个不同 `--output`。

## 后续纵向策略（尚未在本版宣称完成）

1. 以比赛为单位留出验证集，比较候选粒度的壶面紧凑度、历史动作分布稳定性和“状态 + 动作 → 下一状态”分布稳定性；选择满足最小样本量时最小的粒度。不要因 BIC 一直偏好更多簇就假定状态数。
2. 对每一个首手节点，按比分、局号、历史动作分层，计算后续到本局结束的结果分布；这是相关性而不是动作因果价值。
3. 用 Gushue 壶谱的高质量叫球给簇写人能读懂的候选语义，再让教练/规则审查。
4. 对保留下来的“首手目标状态→对手回应”分支，使用本地严格 PhysX 搜索可达性；FGZ/no-tick 作为硬约束。
5. 只有通过“对手最后一壶反击搜索”的终局形，才可以进入防守末端策略。普通聚类中心或三角壳绝不等于安全终局。
