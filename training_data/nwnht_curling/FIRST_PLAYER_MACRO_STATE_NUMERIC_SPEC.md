# 先手宏观状态的数值判定规范

结论：可以使用 47 状态图作为本地 AI 的**状态识别/路由层**，前提是先把本地 PhysX 坐标转换为按钮相对坐标。它不能单独作为出手决策器。

## 坐标转换

NWNHT 特征使用“按钮为原点、前掷线方向为 `+y`”。本地 PhysX 按钮为：

```text
x_button = 2.375 m
y_button = 4.880 m
x_rel = x_local - 2.375
y_rel = y_local - 4.880
```

本地前掷线相对按钮：`10.525 - 4.880 = 5.645 m`。因此不要把 NWNHT 原始的 `6.45 m` 前向上界原样用到本地。

## 基础几何量

| 名称 | 数值定义 |
| --- | --- |
| 营内壶 | `sqrt(x_rel² + y_rel²) <= 1.830 m`（壶心特征阈值） |
| 前场守壶特征 | `1.830 < y_rel <= 5.645 m` |
| 中线守壶特征 | 前场守壶，且 `abs(x_rel) <= 0.380 m` |
| 当前己方/对方营内控制 | 营内壶中，距离按钮最小的一颗属于己方/对方 |
| 可见壶数 | 当前 `enabled=True` 的己方与对方壶数 |

这些是**状态特征**，不是官方计分或自由防守区的定义。特别是“中线壳”只表示满足几何关系，绝不表示营内壶无法被攻击。

## 原始宏观类型：严格优先级

按下列顺序命中第一个条件：

| 类型 | 数字条件 |
| --- | --- |
| `EMPTY` | 总可见壶数 `= 0` |
| `CROWDED_HOUSE_SEARCH_REQUIRED` | 总可见壶数 `>= 5` 且总营内壶数 `>= 3` |
| `OPPONENT_CENTRE_SHELL` | 对方中线守壶数 `>= 1` 且对方营内壶数 `>= 1` |
| `OWN_CENTRE_SHELL` | 己方中线守壶数 `>= 1` 且己方营内壶数 `>= 1` |
| `OPPONENT_HOUSE_THREAT` | 对方当前营内控制，且对方营内壶数 `>= 1` |
| `OWN_HOUSE_CONTROL` | 己方当前营内控制，且己方营内壶数 `>= 1` |
| `GUARD_EXCHANGE` | 总营内壶数 `= 0`，且双方前场守壶数之和 `>= 1` |
| `SPARSE_OPEN` | 上述均未命中，且总可见壶数 `<= 2` |
| `MIXED_CONTESTED` | 其余情况 |

## 数据支持回退

同一个 `Kk × 原始类型` 的历史样本少于 250 条时，运行时改报：

`FIRST_Kk_LOW_SUPPORT_SEARCH_REQUIRED`

该类型不承诺离散战术，必须让 PhysX 搜索。当前回退映射已固化在 `planning_proxy/first_player_macro_state.py`，来自 10,873 个合格历史 end 的 86,984 个先手决策样本。

## 可用边界

- 可以：在任何先手回合从本地坐标稳定返回一个状态 ID，并决定是否必须深搜 PhysX。
- 不可以：把 `OWN_CENTRE_SHELL` 当成安全防御；把 `OPPONENT_HOUSE_THREAT` 一律翻译成清壶；跳过本地 FGZ/no-tick 检查。
- 未完成：每个稳定状态的战术目标、目标状态、失败回退和严格 PhysX 反击验收。
