# 先手八步状态图 v0：重聚类结果

结论：先按先手第几次出手拆开是必要的。第 1 次先手出手自然只有一个空场节点；第 2 到第 8 次都出现了多个壶面拓扑。当前输出有 43 个候选节点，但这不是最终状态数。

## 本次定义

每一个状态仅为：

`(k, 壶面拓扑)`，`k=1..8` 为先手方自己的第几次出手，对应总第 `1, 3, 5, 7, 9, 11, 13, 15` 手。

排除：比分、局号、胜负、领先落后、控分/blank、真实比赛规则资料。前五手的本地规则合法性不作为聚类变量，运行时仅由本地规则和 `k` 验收。

输入壶形是双方壶的可见数量、营内/守壶/中线壶、近似受保护营内壶、纵深 × 横向占位、当前营内比较等结构特征。左右镜像折成同一特征；具体打左侧还是右侧留给 PhysX。

## 可以直接观察到的转移

以下是频数最高的一部分完整两手转移，格式为“本方节点 — 本方动作 / 对手回应 → 下一先手节点”：

- `FIRST_K1_C01 — FRONT / DRAW → FIRST_K2_C05`：2,096 条；
- `FIRST_K1_C01 — DRAW / FRONT → FIRST_K2_C02`：1,954 条；
- `FIRST_K2_C05 — DRAW / DRAW → FIRST_K3_C01`：524 条；
- `FIRST_K3_C05 — CLEARING / FRONT → FIRST_K4_C01`：481 条；
- `FIRST_K4_C05 — TAKEOUT / TAKEOUT → FIRST_K5_C01`：434 条；
- `FIRST_K5_C01 — TAKEOUT / TAKEOUT → FIRST_K6_C05`：444 条；
- `FIRST_K6_C05 — TAKEOUT / TAKEOUT → FIRST_K7_C06`：498 条；
- `FIRST_K7_C06 — TAKEOUT / TAKEOUT → FIRST_K8_C03`：392 条。

这说明状态机边已经能表达“本方选择后，对手怎样回，再轮到本方时变成什么壶形”；但它不表示某条边更优，更不表示其动作在本地 PhysX 下可达。

## 当前不能下的结论

K2–K8 全部达到每步最多 6 簇的上限。因而不能说“每一步刚好 6 个战术状态”，只能说每一步至少需要多个壶形分支。下一轮应当用跨比赛留出验证和最小支持度，选择能稳定复现的最粗粒度；再为保留下来的节点写中文战术语义，并接本地 PhysX。

本轮没有运行 PhysX，也没有把任何节点称为安全构型、最优策略或胜利保证。
