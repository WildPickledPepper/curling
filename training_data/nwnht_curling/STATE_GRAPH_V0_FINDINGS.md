# NWNHT 状态图 v0：第一轮发现与边界

结论：数据链成立，但“应该有几个状态”尚未由 v0 决定。当前最可靠的产物不是策略树，而是一个可复核的全量状态—动作—下一状态表；下一步应先选定稳定的状态粒度，再谈策略推荐。

## 实际覆盖

运行产物：`artifacts/nwnht_four_player_state_graph_v0.json`（诊断版）和 `artifacts/nwnht_four_player_state_graph_v1_exact_shot.json`（已将精确手数作为特征的全量版）。

- 扫描四人赛局：12,411；接受：10,873；因帧不全、投手不交替或壶色归属不能无冲突反推而剔除：1,538。
- 接受局贡献 173,968 条决策样本，即每条 `S_t → A_t → S_(t+1)` 都可追溯到 `end_id:shot`。
- 使用 `Mens_Teams`、`Womens_Teams`、`Mixed_Teams`，显式排除混双。
- v0 在“出手角色 × 手数大阶段”下得到 46 个节点、3,132 条观测边；其中首手方有 24 个节点。
- v1 在相同 173,968 条样本上加入精确手数，得到 47 个节点、3,130 条观测边；首手方前五手的代表节点分别以第 1、3、5 手为中心，说明该特征确实进入了布局区分。

这些数是公开 NWNHT 历史数据和我们的筛选规则所支持的事实。它们不是胜率、最优动作，也不是 PhysX 验证。

## 有价值的横向发现

- 节点确实不是“有敌壶就清”。例如首手前五手的最大节点中，历史上 `DRAW` 6,260 次、`FRONT` 5,257 次，而不是以 take-out 为主；这与前半局建立压力的公开战术方向相容。
- 到 11–14 手，至少存在以 `TAKEOUT` 为主的高频节点，也存在以 `GUARD`、`DRAW` 为主的节点。收束阶段并非单一清场脚本。
- 同一个节点—动作可以通向多个下一节点。例如首手前五手的一个初始/稀疏局面中，`DRAW` 的主要后继有两个不同的后手节点。这正是后续要接“对手回应分布”和 PhysX 可达性的原因。

这些都是**历史相关性**，不能从中推出“选择该叫球导致获胜”。比分、双方实力、执行质量和未检测到的重叠壶都会混杂其中。

## 不能忽略的反证

将每个分区的最大簇数从 6 提升到 12 后，探索产物 `artifacts/nwnht_four_player_state_graph_kcap12_exploratory.json` 在全部 8 个分区都选择了 12 簇（96 节点、9,405 边）。因此简单 BIC + k-means 总想继续细分；46 不是自然状态数，96 也不是。

此外，v0 仅按 `1–5 / 6–10 / 11–14 / 15–16` 四个大阶段分区，尚未把精确手数直接放入特征。v1 已修正该点，但在最大 6 簇下仍有 7 个分区顶格，故 v1 也不应被拿来部署。

## 下一轮如何把它收敛成先手状态机

1. 以**比赛**而非逐手随机切分训练/验证，防止同一场的相邻壶面泄漏。
2. 对候选粒度（例如每精确手数 2、3、4…簇）比较验证集上的三项：壶面到中心的归一化误差、同节点动作分布的训练/验证 JS 差异、`状态 + 动作 → 下一状态` 分布的训练/验证 JS 差异。
3. 设定支持度下限（每个可部署首手节点至少覆盖足够多场不同比赛），选择在三项都稳定时**最粗**的粒度；左右镜像节点再审查是否能合并。
4. 只对这个稳定图上的首手节点，统计“可选目标局面—对手典型回应—失败回退”。把结果与 Gushue 高质量标注交叉命名。
5. 再由严格 PhysX 检查每一个候选目标是否可达、前五手是否合法，以及最后一手反击搜索能否击穿。没有经过这一步的终局节点不得叫“安全”。

## 证据分层

| 结论 | 证据等级 |
| --- | --- |
| 样本量、叫球频数、观测边频数 | NWNHT 公开数据库事实，经本地连续性/壶色筛选 |
| “不是单一清场脚本”的描述 | 由上述频数得到的保守描述 |
| 可部署状态数、推荐目标、胜率提升 | 待验证，v0 不作主张 |
| 路径可达、FGZ/no-tick 合法、终局抗反击 | 必须由本地严格 PhysX 单独验证；本轮未运行 |
