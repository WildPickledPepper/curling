# 九篇论文的统一结论与当前训练决策

> 这不是第十篇论文的摘要，也不重复逐篇精读。它回答一个实际问题：九篇放在一起，到底说明我们现在该训练什么、暂时不该做什么。
>
> 原文依据均来自本目录上一级 `extracted_text/` 的本地全文。文中的“我们采用”是项目决策，不应伪装成论文结论。

## 先说结论

我们不该把训练主线设成“裸 PPO 多跑一些局”。当前最合理的主线是：

```text
严格非扫冰模拟器
  → 战术/策略网络提出少量起点
  → 在连续出手参数附近做有随机性的根搜索
  → 搜索结果（动作分布 + 得分分布）训练策略价值网络
  → 历史模型、脚本和搜索模型混合对局
  → 用先手/后手分开评估，并保留强者
```

这里的“搜索”不是要立刻做完整 16 手大树。现阶段先验证：**同一计算预算下，连续根搜索是否稳定优于固定战术参数**。如果这一步没有独立测试提升，后面的蒸馏只会更快地学习错误老师。

## 每篇论文到底贡献了什么

| --- | --- | --- | --- |
| 01 AlphaZero | 搜索产生的策略分布与对局结果可共同训练策略价值网络。 | 搜索输出必须保存为分布，而不是只留一个“最佳球”。 | 原任务是确定、离散、完全信息游戏；其算力规模不是我们的预算。 |
| 02 AlphaGo Zero | “搜索改进策略 → 网络拟合搜索 → 下一轮更强搜索”是一个闭环；模型和搜索都必要。 | 训练数据格式采用 `(state, search policy, value target)`。 | 其 1,600 simulations/手和数百万盘自博弈是规模参考，不是可直接照抄的超参数。 |
| 03 NFSP | 仅追逐当前最佳响应会让自博弈数据分布剧烈漂移；长期平均策略/历史样本能稳定训练。 | 建 opponent pool，并保留历史检查点和历史数据。 | NFSP 的理论主场是隐藏信息博弈；我们不需先实现两套完整 NFSP 网络。 |
| 04 Elastic MCTS | 粗抽象可提升前期探索，但全程依赖抽象会让最终决策变差。 | 用“先粗后细”：战术候选先缩范围，最终仍以精确物理回放选球。 | 现在不做复杂状态聚类；当前瓶颈不是树节点数。 |
| 05 KR-UCT | 连续动作的相邻结果应按执行误差模型共享；候选动作只是起点，搜索可越过候选集。 | 连续搜索不能只做彼此独立的随机微扰；要逐步改成 kernel 共享的根搜索。 | kernel 必须来自我们的随机机制/校准，不能复制论文的 Student-t 人类投壶误差。 |
| 06 KR-DL-UCT | 网络给连续搜索提供起点和叶子估值；价值预测得分分布比单一均值更适合冰壶。 | 下一代模型输出战术先验、连续修正和 17 档 end 得分分布。 | 论文的 Box2D、静态冰面、5 GPU 一周采样与我们的 PhysX/CPU 条件不同。 |

| 08 Hammer Shot | 最后一壶的目标应是整场胜率，而非本 end 的期望得分；连续目标高度非凸且要考虑风险。 | 最后一壶单独加预算；多 end 后用 WP 表把得分分布转为胜率。 | 它只解最后一壶，不能代替全局布局策略；论文把 sweeping 并入噪声，而我们需把它当显式动作。 |

## 这九篇并不支持的做法

### 1. 不支持把 PPO 当主训练路线

第 07 篇确实比较过 PPO，但它在数字冰壶中给出的优势来自“NFSP + KR-UCT + 两类奖励”的组合，不是“PPO 单独解决连续冰壶博弈”。第 05、06、08 篇共同指出，连续物理动作的局部非凸性和随机性是核心困难；纯策略梯度很容易把大量样本消耗在低价值动作区。

队友 PPO 仍然有价值：它是对手池成员、冷启动模仿来源和独立基线。它不应被当成严格搜索老师。

### 2. 不支持直接照搬“1,600 次搜索”

第 05 篇的 1,600 samples 在每个节点最多向前 rollout 五壶，并把截断局面按 end 评分；第 02 篇的 1,600 次是完全不同的围棋网络搜索；第 06 篇的自博弈用 400 simulations，并用价值网络替代深 rollout。三个数字不能混为一个“论文标准”。

我们应按本机的真实成本制定预算，并以独立局面上的提升来验收，而不是追一个样本数：

1. 固定战术参数；
2. 同预算的连续根搜索；
3. 同预算的“模型候选 + 连续根搜索”；
4. 用搜索时未见的随机序列复测。

只有第 2 步稳定胜过第 1 步，才值得扩大数据采集；只有第 3 步胜过第 2 步，才说明蒸馏模型真的给搜索带来了价值。

### 3. 不支持现在实现完整深树 MCTS 或完整 Elastic MCTS

第 09 篇提醒了树搜索增强会降低每秒模拟数；第 04 篇的实验也不是物理连续动作场景。当前最有信息量的实验是根节点连续优化：它最接近第 05、08 篇的优势来源，同时不会把 16 手的组合爆炸误认为“训练不足”。

### 4. 不支持只报一个混合胜率

冰壶后手优势会掩盖策略问题。每项评测至少报告：

- 有 hammer 时的胜率、平均 end 分、得分分布；
- 无 hammer 时的同三项；
- 对固定脚本、队友 PPO、历史模型、搜索模型四类对手的结果；
- 均值的置信区间或标准误。

## 当前系统与论文前提的对应关系

### 已具备的前提

- **非扫冰的严格物理回放**：本地 PhysX 模拟器已作为训练的动力学底座。它不是“论文里随便一个粗略代理”，应继续通过回归测试防止加速改动改变结果。
- **连续动作与随机摩擦入口**：可对同一出手做多随机序列评估，这是第 05、08 篇所需的“选稳健球”基础。
- **战术候选和终局采集器**：可以把领域知识限制在“给起点”，不把它锁死为最终动作集。
- **多进程根评估**：适合先提高独立候选/局面的吞吐，不急着实现共享树锁与虚拟损失。

### 尚未满足、因此不能越过的前提

1. **连续 kernel 搜索尚需独立验证。** 当前 P0 的小预算结果只可当 smoke test；必须在预先固定的局面集和未见随机序列上比较固定战术基线。
2. **没有经验证的 value network。** 前 11 手若直接截断并看临时 house 分，会把“临时占优”错当作 end 得分。前期搜索只能使用固定 continuation，或等 P1 价值头通过验证后再截断。
3. **扫冰不在当前交付边界。** 本文路线只保证非扫冰；不能把非扫冰的训练结果宣传成含扫冰策略的强度。
4. **多 end 目标尚未接入。** P0 先优化单 end 得分；只有得到可靠的得分分布后，才可按第 06、08 篇接入 WP 表。

## 推荐的实施顺序

| 阶段 | 做什么 | 完成标准 | 依据 |
| --- | --- | --- | --- |
| P0：验证搜索老师 | 固定 20–50 个涵盖空场、守壶、单/双碰撞、最后一壶的非扫冰局面；固定总物理预算。 | 连续根搜索相对固定战术库的提升在独立随机序列上为正，并分先后手报告。 | 05、08、09 |
| P1：生成并蒸馏数据 | 保存完整状态、候选权重、连续参数、17 档得分直方图；训练小型策略价值网络。 | “模型候选 + 同预算搜索”超过纯搜索或至少等价但更快。 | 01、02、06 |
| P2：稳定自博弈 | 脚本、队友 PPO、历史快照、小预算搜索组成对手池；保留历史样本。 | 新模型不能只赢最新自己；通过固定对手池的晋级门槛。 | 03、07 |
| P3：比赛目标 | 根据比分、剩余 end 与 hammer 身份建立 WP 表；最后一壶提高预算。 | 领先时更稳、落后时允许搏分的选择，在预注册局面上提高预期整场胜率。 | 06、08 |
| P4：扫冰 | 单独建模“何时询问、何时生效、摩擦如何变化”。 | 与 Unity/比赛协议逐 tick 对齐后才进训练。 | 05、08 的局限，不是其现成方案 |

## 状态、动作和标签的最小约定

为避免把“先手/后手问题”再次混在一起，所有训练样本至少应保存：

```text
state:
  当前出手方视角的全部壶位（严格回放保留 yaw）
  shot index / remaining shots
  当前出手方、hammer 身份、当前 house 领先方和临时得分
  多 end 时的剩余 end 与当前出手方视角分差

teacher target:
  根候选的搜索权重（不是只存 argmax）
  选中连续参数 (v0, h0, w0)；扫冰启用后再加入 sweep
  每个候选的样本数、均值、方差/LCB
  当前出手方视角的 17 档 end 得分直方图
```

## 一个容易混淆、但必须守住的边界

**模拟器不是老师；搜索才是老师。**

模拟器只负责回答：“这个给定动作在这条随机序列下会怎样。”

老师是“在许多动作、许多随机序列和明确目标之间作比较”的搜索过程。策略网络则学习把搜索的优先级快速提出来。把三者分开，才能知道性能提升究竟来自物理正确、搜索正确，还是模型真的学会了。
