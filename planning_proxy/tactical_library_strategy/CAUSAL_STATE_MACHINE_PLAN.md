# 先手经验状态机与目标局面库推进计划

> 文件名保留为历史兼容；本计划不再把公开观察壶谱表述为“因果边证明”。

## 一句话结论

我们要构建的不是“见敌壶就清”的脚本，也不是从零训练的强化学习策略，而是一个：

> **由历史连续壶谱估计的、有限时域、层级经验 MDP（状态机）**。

它做两件分离的事：

```text
战术层：当前棋盘 -> 离散状态 S -> 排序后的目标局面 G1/G2/G3
执行层：已选 G -> 本地规则过滤 -> PhysX 反解 v/h/w
```

PhysX 不定义状态、不从历史中筛战术、不参与目标局面价值排序；它只在最后尝试把已选
目标局面实现出来。当前搜索预算内找不到路径，只表示“未找到”，不等于物理无解。

## 1. 决策边界：什么进入模型，什么不进入

运行时输入固定为：

```text
先手本 end 第 K 壶（K=1..8） + 当前所有静止壶的 owner/坐标
```

明确不进入运行时状态或价值函数：

- 整场比分、局号、下一局后手、blank/控分偏好；
- 队伍、赛事、投手、真人叫球文字；
- 历史终局结果；
- PhysX 路径、v/h/w、反解预算、搜索是否命中。

因此本模型优化的是**本 end 的固定结果目标**，不是整场控分。终局标签保留：

```text
Y = first_end_margin
  = 本 end 结束时，先手得分减对手得分
```

同时报告 `FIRST_SCORES / BLANK / OPPONENT_SCORES` 概率。若以后允许读取比分/局号，
可另建“整场控分 MDP”；不能把它偷偷混进当前模型。

## 2. 数学模型

### 2.1 决策时刻

每次轮到先手出壶才记一个时刻：

```text
B_k --phi--> S_k --选择 G_k--> U_k --对手回应--> B_(k+1) --phi--> S_(k+1)
```

| 符号 | 含义 |
| --- | --- |
| `B_k` | 第 K 次先手出壶前的精确棋盘坐标。 |
| `S_k=phi(B_k,k)` | 可解释的离散战术状态。 |
| `G_k` | 本手希望形成的**目标局面约束**，不是叫球名，也不是 `v/h/w`。 |
| `U_k` | 己方出手、对手回应前的实际棋盘。 |
| `S_(k+1)` | 对手回应后下一次先手决策状态；K8 后为终局。 |
| `Y` | 本 end 的终局价值。 |

对手不是当前模块控制的行动者；其历史回应被吸收进经验转移：

```text
P_k(S_(k+1) | S_k, G_k)
```

这使当前版本是先手视角的 MDP。未来若把对手策略显式建模并取最坏回应，才升级为双人随机博弈；不能把历史平均回应误说成最坏情况保证。

### 2.2 倒推价值

K8 直接由终局结果估值：

```text
Q_8(s,g) = E[Y | S_8=s, G_8=g]
```

K1--K7 向后递推：

```text
Q_k(s,g) = Σ_s' P_k(s' | s,g) · V_(k+1)(s')
V_k(s)   = max_g Q_k(s,g)
```

实际战术价值按经验 `Q` 均值排序；bootstrap 下界不冒充另一个战术目标，而是作为不确定性与风险证据：

```text
rank(s,g) = Q_mean,k(s,g)
confidence(s,g) = [LCB_bootstrap(Q_k), UCB_bootstrap(Q_k), support, holdout_diagnostic]
```

低支持候选先被支持门淘汰；留下的候选再按 `Q_mean` 排序，并同时显示样本数、留出集稳定性、对手回应风险和终局结果分布。

## 3. 状态：横向把棋盘映射为可解释类别

状态不是 KMeans 簇号，也不是只数壶。它由 `K + 坐标派生特征` 确定，左右镜像归一，前后不镜像。

```text
S = (K, 控分关系, 营内分区占位, 守壶分区占位, 几何关系)
```

特征包括：

- 空营/先手控分/对手控分/近似不确定；
- 双方在按钮、前营左/右、后营左/右的 `0/1/2+` 占位；
- 双方中线、左翼、右翼守壶的近/远分布；
- 可见壶数与营内壶数的精确宏观计数；
- 同色守壶对营内壶的几何遮挡代理；
- 对方营内单清/双清组合的几何代理。

“被守壶遮住”只是一项坐标特征，绝不表示后方壶安全；中线守壶也不是无敌盾。

己方结果、对手回应、下一状态、终局结果分布均有稳定差异。状态数不是预先指定为 47、95 或任意数字。

## 4. 动作：战术动作 A 与精细目标局面 G，而不是出手参数或真人意图

对同一状态 `S`，数据中可能出现多个不同的出手后终局形态。例如：

```text
G1：当前最近的对方营内壶必须出界；我方出手壶可出界或停在侧方。
G2：对方壶保留；我方新增壶停入按钮左前的圆形区域。
G3：两颗当前对方营内壶必须出界；若失败，结构回退为 G1。
```

为避免把每个 0.20m 落点都误当成独立战术，动作采用两层：

```text
S_k -> A_k（战术结果类型） -> G_k（精细终局约束）
```

例如 `A=近中线守壶` 下可保留多个 `G`：各自仍是半径约 0.17m 的窄落点、相同的己方守壶占位和不同的精细中心。数据倒推先给 `A` 排序；执行阶段才依次尝试其保留的 `G` 子目标。**这不是扩大目标区域，也不是合并状态。**

中线守壶近/远、翼守壶近/远沿用现有坐标分区；按钮、前营左/右、后营左/右仍不同。只有结构相同且属于同一语义战术区域的精细 `G` 才归入同一个 `A`。

历史记录只需证明某种 `S -> U` 终局形态发生过；无需知道真人当时主观想打什么。真人意图不影响“G 是否能作为候选目标局面”这一件事。

但必须保守处理数据限制：NWNHT 同色壶没有跨帧永久 ID。只有身份可逻辑恢复时才输出具体壶选择器；否则输出区域占位/壶数约束，或弃权。不能伪造“历史上清掉了当前第几号壶”。

## 5. 纵向状态机：从连续记录估计转移

对每个 `(S_k, G_k)`，保存而不是丢弃：

```text
目标后己方形态 U_k 的分布
对手回应后的下一状态 S_(k+1) 分布
本 end 终局结果 Y 的分布
样本数、开发/留出支持度、分布漂移
```

这就是经验边：

```text
S_k -- G_k --> {P(S_(k+1)), P(Y), support, risk}
```

它回答的不是“这个目标在真人比赛里是否一定导致胜利”，而是：

> 历史上，在这种离散局面下打成这个目标后，局面通常如何被对手回应，并通常通向哪些后继状态和 end 结果？

## 6. 下一阶段：从 K8 倒推给 G 排序

这是当前应实现的主工作，**不接 PhysX**。

### 6.1 冻结数据划分

1. 按 `match_id` 分组切开发集和最终留出集；同一比赛的相邻壶不得拆开；
2. 仅用开发集冻结状态规则、目标模板、支持门和奖励定义；
3. 留出集只做排序稳定性与预测验证，不事后改阈值挑结果。

### 6.2 经验转移与平滑

对每个状态—目标边统计 `P(S'|S,G)`；低支持边采用 Dirichlet/Laplace 平滑，
但平滑不能把无样本边制造成可推荐边。

部署候选最少同时满足：

- 开发集支持数、留出集支持数达到预注册门槛；
- 目标后形态和对手回应分布在两侧的总变差距离不超过门槛；
- K8 有足够终局观测；
- 目标约束能在当前精确棋盘动态绑定。

### 6.3 反向动态规划

按 `K=8,7,...,1` 依次计算 `Q` 与 `V`：

1. K8 用平滑后的 `first_end_margin` 分布计算价值和 bootstrap 下界；
2. K1--K7 用下一状态分布加权 `V_(k+1)`；
3. 对每个状态按 `Q_mean` 排序；LCB/UCB 只作为置信与风险诊断；
4. 同时报告 `P(FIRST_SCORES)`、`P(BLANK)`、`P(OPPONENT_SCORES)`、低分位风险；
5. 目标结果近似重复的候选只留最高保守值者，避免 K1 返回几十个相近落点；
6. 每状态输出 1 个主目标和最多 2 个**结果形态不同**的回退目标；没有合格目标则 `SEARCH_REQUIRED`。

排序是历史经验价值排序，不是“真人数据给出数学因果证明”。本项目不使用真人意图来定义 `G`，也不需要用真人意图来生成候选库。

### 6.4 留出验证

冻结排序后，在最终留出比赛中报告：

- 每个状态/目标的支持和覆盖；
- 预测的下一状态分布与实际分布差异；
- 主目标与其他历史实际目标的终局结果关联差；
- 排序方向在开发/留出集是否一致；
- 哪些状态因低支持或漂移只能 `SEARCH_REQUIRED`。

这验证的是经验状态机的泛化与排序稳定性，不声称单靠观察壶谱已完成真人世界因果证明。

## 7. 运行时接口：战术模块唯一输出

```text
输入：exact_board, own_throw_number
输出：StatePlan
```

`StatePlan` 至少包含：

```text
state_id
state_support / evidence_status
primary_goal
fallback_goals[0..2]

每个 goal：
  goal_id
  StoneConstraint / OccupancyConstraint / ActiveStoneRegion
  expected_next_state_distribution
  Q_mean / Q_LCB / support / holdout_stability
  rule_notes
```

战术模块不输出 `v/h/w`，不自行调用 PhysX，不将“未找到路径”解释成策略失败。

## 8. PhysX：最后的独立执行层

只有战术层已排序后才调用：

```text
primary_goal
  -> 本地规则过滤（尤其前五手 FGZ）
  -> 粗代理 + 严格 PhysX 尝试反解
  -> 命中则执行
  -> 当前预算未命中则尝试 fallback_goal_1 / fallback_goal_2
  -> 全部未命中：SEARCH_REQUIRED
```

前五手规则由本地规则实现判定：不能把对方自由防守区壶打出界；中线守壶与普通守壶的受限方式必须区分。规则过滤不是状态特征，也不参与历史价值排序。

K8 的每一个实际 PhysX 终局仍必须经对手最后一壶反击搜索；其目的不是宣称绝对安全，而是记录对手是否存在 direct、raise、runback、double 或窄门反击。先手的目标是建立压力、保住得分层、提高对手末壶难度，而不是保证对手永远不能得分。

### 9.2 层级动作层与五折重复检查（2026-07-17）

为解决“同一战术被切成几十个 0.20m 细点”的问题，已新增：

- `build_tactical_goal_library_v1.py`：将 112 个精细 `G` 合为 25 个父战术动作 `A`；
- `rank_tactical_goal_library_v1.py`：只给父动作倒推价值，但把每个父动作下的窄 `fine_goal_options` 原样带给未来执行层；
- `summarize_tactical_crossfold_v1.py`：汇总 5 个按比赛划分的外层留出折。

本层严格是：

```text
S（当前壶面状态） -> A（战术结果类型） -> G（精细终局约束）
```

不是合并 `S`，也不是把 0.17m 的精细 `G` 扩大成一个可任意落壶的大圆。守壶近/远、按钮、前营左/右等
仍依现有坐标语义分开；父动作只持有若干窄 `G` 子目标。

五折结果：

- K1 空场由 87 个细目标变为 6 个父动作；`BUTTON` 在 5 折中 4 次为开发集首选，`CENTRE_GUARD_NEAR`
  有 1 次首选；K1 的平均开发/留出排序 Spearman 为 `0.563`，留出首选平均名次为 `2.0`；
- K2 `FIRST_HOUSE_CONTROL` 的首选只达到 `0.4` 折一致性，不能冻结为动作规则；
- 大多数后段状态只有 1--2 个被当前结构门保留下来的动作，无法做“多个动作谁更好”的排序验证；它们不应因
  `mode_share=1.0` 被误称为“策略稳定”，而是“当前候选覆盖不足”。

因此目前只得到一个**需要继续审查的 K1 按钮层经验候选**，还没有可部署的完整先手策略树。下一轮应对
K1 的精细子目标做条件化排序/稳定性检查，并扩大其他状态的可表达动作覆盖；依然不进入 PhysX。

### 9.3 动作支持门上移后的覆盖审计（2026-07-17）

`v1` 动作层仍只合并了已经通过“单个 0.20m 细格支持门”的 112 个 `G`，因此只能覆盖 13 个状态。审计显示，
其余状态并非无数据：细格支持 `<30` 才是主淘汰原因。

新建 `build_tactical_goal_library_v2.py` 后，父动作 `A` 的定义仅保留：

```text
source_state + 终局类型 + 对方移出数量/营内移出数量 + 新壶语义目标区
```

具体壶绑定、碰撞后全场占位、窄坐标圆形区域仍全部留在子目标 `G`，不参与父动作的支持计数。首轮结果：

- 63,394 条可表达历史模板；
- 401 个支持至少 30 的父动作；
- 49,315 条 `S -> A -> G` 记录；
- 在第 4 个比赛留出折，62 个状态有可倒推父动作、46 个状态有至少 3 个可比较父动作。

但同一审计也否定了一个错误的泛化：**不能要求 K2--K8 的精细 `G` 在全局绝对坐标中跨折反复出现。** K1 空场时，
按钮层的三个窄圆形目标可在每折重复出现；后续复杂局面中，正确的精细落点依赖当前具体壶坐标。这不是放宽精细
约束，而是说明精细目标必须建模为：

```text
G = G(B_exact, A)
```

下一阶段新增“条件精细目标”层：在已选 `S,A` 内，按当前精确棋盘从相似历史棋盘检索对应的窄 `G`，并用留出
比赛检验检索到的终局约束是否仍贴近真实后继局面。父动作本身不能直接传给 PhysX；没有经条件检索支持的 `G`，
仍必须 `SEARCH_REQUIRED`。

最近棋盘的终局点都没有比随机同动作历史点更接近真实留出终局（`0.408m vs 0.388m`；`0.560m vs 0.493m`）。

因此不实现朴素最近邻条件目标模块。运行时目标精度改为证据分级：

```text
NARROW_CROSS_FOLD_GOAL  : 跨折可复现的窄圆形 G（目前只在 K1 BUTTON 证实）
SEMANTIC_REGION_GOAL   : 按钮/近中线守壶/前营侧区等区域谓词 + 动态清壶角色约束
SEARCH_REQUIRED        : 没有支持足够的父动作或终局约束
```

第 2 类仍是可执行的“目标范围”，但不是伪装成固定精确坐标的终局。它会增加未来路径搜索范围；这是现有壶谱对
精度所能支持的真实边界，不能用未经验证的相似局面检索来掩盖。

### 9.5 运行时 StatePlan 接口（2026-07-17）

已生成 `artifacts/nwnht_first_player_runtime_state_plan_v1.json` 与
`runtime_state_plan_v1.py`。接口的唯一运行时输入是：

```text
own_throw_number K + 当前所有静止壶的 owner/x/y
```

它调用冻结的 v2 状态分类，再返回对应的 `primary_action`、至多两个结果形态不同的 `fallback_actions`、
预期下一状态分布与精度等级。五折共识门为“父动作在至少 4/5 折为首选、并在至少 4 折可排序”。结果：

- 95 个状态中，42 个输出 `EMPIRICAL_ACTION_CONSENSUS`；
- 其中 1 个是 `NARROW_CROSS_FOLD_GOAL`（K1 空场 `BUTTON`，3 个窄圆形终局候选）；
- 41 个是 `SEMANTIC_REGION_GOAL`；
- 其余 53 个按低状态支持、动作不稳定、无跨折动作或无可绑定终局目标，明确返回 `SEARCH_REQUIRED_*`。

接口会把规范化过程中的左右镜像还原到调用者原坐标系；不改变规范化状态 ID，也不读取比分、局号、队伍、赛事、
真人叫球、规则合法性或 PhysX 搜索结果。

这完成了战术层到“目标范围/终局约束”的静态接口；尚未声称这些目标在本地物理中可达。下一阶段才是本地规则过滤、
PhysX 反解和预算失败切换，且必须把“未找到路径”记录为搜索未命中而非物理无解。

### 9.6 现有 GoalState / PhysX 接口只读审计（2026-07-17）

已只读检查 `planning_proxy/goal_state_tactics`。它已经具备“候选 GoalState -> 本地规则/严格终局验收 ->
未命中时尝试回退”的正确控制流，但不能直接接入本计划的新 StatePlan，原因是：

- 它使用旧的 `state_key`/collision 状态，不是 v2 的 95 个可解释状态；
- 它把本地 PhysX 坐标转换为旧 NWNHT 按钮中心坐标，而新的 StatePlan 已在规范坐标系中给出镜像可还原约束；
- 其现有 `CircleRegion` 只能表达圆，而 `SEMANTIC_REGION_GOAL` 还包含前营扇区、近/远中线通道、翼区等非圆区域。

因此**不允许**把语义区域随意压成一个圆、也不允许把 v2 状态硬塞进旧状态键。最后一阶段应新增独立适配层：

```text
v2 StatePlan + 当前本地棋盘
  -> 坐标/左右镜像转换
  -> 可表达的圆形子区域或新区域谓词
  -> 本地规则过滤
  -> 严格 PhysX 反解与终局验收
  -> 未命中则下一 G/A；不宣称物理无解
```

这一步必须先明确路径规划器究竟支持“区域谓词”还是只支持“圆形终局约束”，再做小规模严格 PhysX 夹具；当前不修改
旧 `goal_state_tactics`，也不把战术模块的 42 个共识动作说成已物理验证。

### 9.7 非圆语义区域的圆形内近似（2026-07-17）

路径层现有契约只接受圆形终局目标。新增独立的
`planning_proxy/tactical_library_strategy/semantic_region_circle_adapter.py`，用于把运行时语义区域转换为圆形子目标：

- `BUTTON` 是精确圆，原样传递；
- 前营扇区、近/远中线通道、翼区生成一组**完全内含**的小圆；
- 中线网格以 `x=0` 对称生成，不让网格起点形成假左/右偏好；
- 每个子圆显式带 `INNER_APPROXIMATION_ONLY`；全部未命中只表示当前圆覆盖和搜索预算未命中，绝不表示原区域物理无解。

这解决了“区域谓词如何不失真地降到圆形路径输入”的几何表示问题，但还没有把圆从 NWNHT 规范坐标转换到本地
PhysX 坐标，也没有调用路径搜索。下一步是写最小坐标/GoalState 适配夹具，只对 K1 窄圆和语义区域的圆形子目标
做少量严格终局验收，不做大规模采样。

### 9.8 本地圆形终局请求适配（2026-07-17）

新增 `planning_proxy/tactical_library_strategy/v2_circle_goal_adapter.py`。它接受本地棋盘与 v2 StatePlan，输出按
主/备战术顺序排列的 `CircleGoalRequest`：

- 当前本地坐标先转换为按钮中心规范坐标做 v2 状态判定；
- 每个规范圆以 `local_x = HOUSE_X + canonical_x`、`local_y = HOUSE_Y + canonical_y` 转回严格 PhysX 本地坐标；
- K1 空场实际冒烟输出 9 条圆形请求：主 BUTTON 的 3 条窄圆，及两个回退动作各 3 条窄圆；
- K2 空场近中线语义区输出 6 条 `INNER_APPROXIMATION_ONLY` 圆，全部在原通道内；
- `SEARCH_REQUIRED` 不生成圆形请求。

这个适配器不修改旧 `goal_state_tactics`，也不自称已完成 `GoalState` 的所有匿名壶/终局占位约束。当前它只表达
已有数据能够诚实支持的“出手壶最终圆形范围”；严格 PhysX 后必须重新检查本地规则、最终壶面和（K8）对手末壶反击。

### 9.9 v2 圆域接入既有粗代理 / Newton-MADS 求解器（2026-07-17）

此前对现有求解器的审计不完整：`evaluate_vs_teammate_ppo.py` 中已有一条可用的连续链，实际结构是：

```text
粗代理全局网格给 v/h/w 初值
  -> 严格 PhysX 回放排除代理假阳性
  -> 净空落位用数值雅可比的阻尼 Newton
  -> 擦壶/碰撞/病态雅可比时切换 MADS
  -> 多摩擦序列终局、FGZ 与己方损失验收
```

新增独立 `physx_goal_bridge.py`，只将 v2 的 `ACTIVE_STONE_PLACEMENT` 圆域编译成这个已有求解器所需的
`target_points + landing_region_radius_m` 兼容输入。旧策略、旧比赛入口均未修改。它按 StatePlan 给出的主圆、
同动作备圆、备动作圆依次尝试；`NOT_FOUND_WITHIN_BUDGET` 明确不是物理无解。

K1 空场的跨折 BUTTON 窄圆做了最小真实验证：3 条摩擦序列下，425 条粗代理初值、23 次严格 PhysX 调用，
Newton 给出最坏落点误差 `0.038637m < 0.173160m` 的合规解。完整记录在
`tactical_library_strategy/PHYSX_BRIDGE_AUDIT.md`。这是单个接口闭环与单目标物理可达的证据，**不是**整套策略胜率或
42 个共识动作可达性的证明。

碰撞类动作没有被假接：它们必须先获得“哪些当前壶出界/保留/进哪个范围”的 v2 终局约束，才能接 MADS 碰撞支路；
否则宁可返回 `REQUIRES_COLLISION_GOAL_CONSTRAINTS`，也不允许退化为默认清壶。

### 9.10 碰撞终局契约与单目标 MADS 桥（2026-07-17）

父动作的支持门上移是正确的，但执行时仍必须知道“清哪颗当前壶”。新增
`build_collision_goal_contracts_v1.py` 从父动作之下的细目标中提取匿名、可运行时绑定的碰撞契约：

```text
S + A(移出数量/出手壶语义落区)
  + 当前对方营内壶的几何角色
  -> 指定 slot OUT_OF_PLAY + 出手壶区域
```

160 个历史移出对方壶父动作中，115 个通过“父支持 >=30、绑定在保留细目标中占 >=80%、绑定数量与移出数量一致、
滚位区可表达”的门。它们都是单目标移出；45 个被明确拒绝，双飞并未被错误降成单清。

`physx_goal_bridge.py` 现在可先重做 v2 状态分类并恢复左右镜像，再把这些单目标契约交给已有的粗代理/严格
PhysX/MADS 支路。契约额外要求指定目标在每条序列真的 `enabled=false`：旧求解器的“推到废球带也算清”不能冒充
`OUT_OF_PLAY` 成功。

一条来自契约自身真实历史前态的 K2 冒烟，状态/镜像/slot 绑定均正确，但在 4305 粗初值、30 秒、1 条摩擦序列下
返回 `NOT_FOUND_WITHIN_BUDGET`。这严格记录为搜索未命中，绝非物理无解或清壶策略反证；且该父动作尚未通过运行时
跨折共识门。详见 `tactical_library_strategy/COLLISION_CONTRACT_AUDIT.md`。

### 9.11 双飞的匿名整盘终局目标（2026-07-17）

双飞不应因 `active_final_point` 缺失而退化成“只要清两颗就行”。该字段缺失的真实原因是 NWNHT 同色壶无跨帧
ID，碰撞后无法可靠区分本次出手壶与被撞动的旧己方壶；它不表示出手壶落点不重要。

新建 `build_double_outcome_goal_contracts_v1.py`，把双飞拆为：

```text
两颗当前绑定对方营内壶 OUT_OF_PLAY
  + 匿名 post-own 全盘构型（按钮/四扇区/控制/保护壶/宏观形态）
```

两个双飞父动作（K7 支持 31、K8 支持 45）得到 9 个结果分支。按比赛分组的五折支持是每个分支在五个独立
比赛组各出现的次数；例如 K8 清双后空场是 `13, [3,3,1,4,2]`，K8 清双后己方按钮控制是
`6, [1,1,1,2,1]`。这是跨比赛复现检查，**不**是价值、因果或物理可达证明。

`double_outcome_goal.py` 现能在严格 PhysX 的实际 slot 终局上验证“两目标都出界 + 匿名全盘构型”。后续已补上
独立多目标 MADS，但尚未认证任何双飞可执行解，也不进入运行时动作推荐；K8 还必须接末壶反击搜索。详见
`tactical_library_strategy/DOUBLE_OUTCOME_CONTRACT_AUDIT.md`。

### 9.12 双目标严格 PhysX / MADS 闭环（2026-07-17）

新增独立 `double_mads_solver.py`。它不复用旧单目标“清某一颗即可”的成功条件：粗代理只筛出先撞两目标之一的
入射分支，严格 PhysX MADS 的每次目标函数同时检查两 target slot 出界、匿名整盘构型、规则合法性和己方损失。

对 K8 跨五折“清双后空场”契约的原始历史样例 `389:15`，重新分类、镜像恢复、目标绑定均一致；在 4305 条粗代理
候选中有 605 条首撞目标分支。父分支选择器先各保留“先撞每一个目标”的一条路线，再按攻击分补齐 3 条；4 轮
MADS、1 摩擦序列下做了 99 次严格回放，结果仍为 `NOT_FOUND_WITHIN_BUDGET`。因此该结果不是“只撞到其中一颗壶”
造成的遗漏，但仍只是当前初值覆盖/预算下的未命中，不是物理无解，也尚未进入三摩擦或 K8 反击验收。失败详情会记录
合法样本数、最少剩余目标数和最小拓扑差，以决定下一步究竟改哪一层。完整数字写入
`DOUBLE_OUTCOME_CONTRACT_AUDIT.md`。

该夹具的诊断结果进一步显示：99 次回放均合法，最优合法候选已经双清（剩余目标数 0），但匿名终局的 `macro`
仍差 1 项，且己方被清 1 壶。当前障碍因此是“双清后没有形成所要求的整体局面”，不是碰撞不到、不是 FGZ，
也不是双飞已经通过验收。后续必须先从数据上区分这类碰撞链的后继形态，不能仅增加 MADS 预算。

### 9.13 双飞后继形态的终局证据（2026-07-17）

原 v1 双飞契约已经区分 `EMPTY`、`GUARD_EXCHANGE`、`SPARSE_OPEN`、己方营内控分层等匿名终局形态；
v2 工件在不覆盖 v1 的前提下，为每个形态加入历史轨迹的终局标签分布。这样“清双后 EMPTY”不再被误当成
唯一双飞目标：K8 对方营内威胁的 45 条双清记录中，EMPTY 13 次、SPARSE_OPEN 6 次、GUARD_EXCHANGE 6 次、
两类已支持己方营内控分层合计 11 次。

这些 K8 分支的历史终局均未出现先手得分；EMPTY 为 `0 / 9 / 4`（先得分 / blank / 对手得分），其余分支也为
`0 / blank / 对手得分`。这是观察性轨迹标签，不把它当成因果分支价值；但它已经足以否定“选 EMPTY 双飞就是
赢法”的错误说法。运行时若将来启用双飞，必须由倒推 Q、跨折支持、终局拓扑和严格 PhysX 一起筛选，而不是仅以
双清是否成功来推荐。

### 9.14 目标局面 G 的五折倒推排序（2026-07-17）

此前的父动作 `A` 不能直接送给规划器；新增目标结果层，把每条记录编译为：

```text
S -> A（移壶/放壶的战术类型）
  -> G（完整 post-own topology + 最多三个细终点/动态绑定约束）
  -> S' / END
```

49,315 条父动作实现记录得到 2,006 个支持至少 3 次的目标局面 `G`（35,921 条对应
观测）；11,802 个低支持结果被拒绝。`G` 不是单一“落点标签”：它同时携带匿名整盘
终局谓词和细终点/清壶绑定菜单，执行层必须两者都满足。

对仅在五个比赛折都出现的 `G`，使用 K8 到 K1 的同一经验倒推过程分别做五次外层
留出。只有某个 `G` 在至少 4/5 折都成为该状态的首选，才作为目标局面共识输出。结果：

- 30 个状态有 `EMPIRICAL_GOAL_OUTCOME_CONSENSUS`；
- K7、K8 的 `OPPONENT_HOUSE_THREAT`（包括双飞父动作）均为
  `SEARCH_REQUIRED_NO_CROSS_FOLD_GOAL_OUTCOME_CONSENSUS`；
- 因此双飞仍只是受审计的目标候选，**没有**被偷偷升级成运行时推荐；
- 每个共识 G 仍只是历史轨迹关联排序，不是因果保证、规则认证或 PhysX 可达结论。

新工件为 `nwnht_v2_tactical_goal_outcome_library_v2.json` 与
`nwnht_v2_tactical_goal_outcome_value_v1.json`。下一阶段应把这 30 个 G 做成独立的
运行时 GoalState 接口，并让旧的 StatePlan 只在“父动作与 G 共识均存在”时输出它；
其他状态继续 `SEARCH_REQUIRED`。在此之前不继续扩大双飞 MADS 搜索。

### 9.15 G 级运行时接口（2026-07-17）

新增 `runtime_goal_outcome_plan_v1.py`，冻结加载 v2 状态划分和目标级五折价值表：

```text
canonical board + K
  -> classify_runtime_state
  -> primary_goal / fallback_goals
  -> terminal_board_predicate + fine_goal_options
```

它不读取比分、局号、队伍、真人叫球、规则判定或 PhysX 结果。调用者棋盘若在镜像侧，
接口会还原细终点圆、动态选择器的来源区、营内占位和终局谓词的 LEFT/RIGHT；规范状态 ID、
五折计数和价值证据不变。K8 双壶对方营内威胁的真实夹具测试明确返回
`SEARCH_REQUIRED_NO_CROSS_FOLD_GOAL_OUTCOME_CONSENSUS`，不输出伪造的双飞目标。

该接口当前输入为 NWNHT 按钮中心规范坐标。它只完成战术输出，不可直接把规范坐标送入
本地 PhysX；下一阶段才可写一个小型本地坐标/终局验收适配器，并仅对有 G 共识的状态调用。

### 9.16 同 K 共享目标模板的失败对照与条件化方向（2026-07-17）

为补齐其余状态的候选集，试验了“固定 K 下共享 post-own 语义模板”的池化原型。87,000
余条端点得到 327 个支持至少 30 次的同 K 模板；它能给 95 个 S 都返回候选，但 66/95
首选在该 S 没有直接实现记录，且 K3 的 17 个状态全部偏向同一模板。这个简单均值池化
会抹平局面差异，明确**不进入运行时**。

随后只在同 K、同宏观局面内，按守壶、按钮、营内分区、双壶关系等运行时特征相似度做
条件化核加权诊断。它给 94/95 个 S 找到候选，K4 的 11 个状态已有 7 种首选模板，说明
“共享模板 + 条件化 S”方向有效；但 K3 仍有较大模板复用，且尚未做外层五折验证。因此
下一步是把该条件估计器固定为可复现模型、按比赛做五折训练/留出，再和直接证据规则
比较；在通过前不得用它填补 `SEARCH_REQUIRED`。

### 9.17 条件化共享模板的五折审计与证据分层（2026-07-17）

条件估计器现已按比赛做五折训练/留出：每一折仅在相同 K、相同宏观局面内共享模板，
再以状态的可运行时几何特征作核加权；K8 到 K1 仍按历史后继做倒推。它绝不跨 K 共享
实际目标局面。门槛为训练模板支持至少 10、同一首选模板至少赢得 4/5 折、该状态—模板
组合在被留出比赛中的直接观测合计至少 5 条。

结果为：23/95 个状态达到条件化模板共识，58 个仅审计记录，14 个没有候选。23 个中仅
7 个与原有 30 个精细 G 共识重合；其余 16 个是新增的**语义**补充。因此目前证据表是：

- 30 个 `DIRECT_FINE_GOAL_CONSENSUS`：已有整盘终局谓词和细终点/动态清壶绑定，才可成为执行层候选；
- 16 个 `CONDITIONAL_SEMANTIC_GOAL_CONSENSUS_PENDING_FINE_COMPILATION`：已有独立五折和直接留出支持，
  但只有“清一颗对方营内壶后形成先手前营层”等语义终局，尚无该 S 专属的细圆形落点/绑定；
- 49 个仍为 `SEARCH_REQUIRED_NO_HIGH_CONFIDENCE_GOAL`。

这三类由 `build_goal_evidence_registry_v1.py` 合并，输出
`nwnht_v2_goal_evidence_registry_v1.json`。直接 G 永远优先；条件化语义项不能被送给路径规划器，
下一步必须从其同 K、同模板、相似来源状态的历史实现中编译细终点或动态清壶绑定，再重新做留出检查。
这使总覆盖的“高证据目标方向”达到 46/95，但**可执行精细 GoalState 仍只有 30/95**；不把这两件事混为一谈。

### 9.18 条件化细终点/绑定编译的否定结果（2026-07-17）

对上节新增的 16 个语义项，`compile_conditional_fine_goals_v1.py` 只取相同 K、相同语义终局
的历史实现；在每个比赛留出折中按出手前几何特征加权，重新聚合细圆形落点、匿名壶选择器和动态营内清壶绑定。
细约束必须在至少 4/5 折保持首选，且在这些留出折中有至少 3 条该**源状态—细约束**的直接实现。没有端点、
选择器或绑定的“仅语义终局”会被明确拒绝，不能偷渡成细目标。

结果：`nwnht_v2_conditional_fine_goal_audit_v3.json` 中 16 项为 4 个 `AUDIT_ONLY`、12 个
`NO_FINE_CONSENSUS`、0 个 `CONDITIONAL_FINE_GOAL_CONSENSUS`。因此条件化模板目前只扩大了研究
候选覆盖，**没有扩大运行时可执行覆盖**；执行层仍只接收 30 个直接五折精细 G，另外 65 个状态仍返回
`SEARCH_REQUIRED`。这是数据不足/细终点多峰的诚实结论，不把均值圆或无约束清壶伪造成解。

### 9.19 修正为完整的 `S_k -> G_k -> S_(k+1)` 语义 MDP（2026-07-18）

此前错误地把“有一个可执行的精细圆/绑定”当作“G 存在”的前提，造成 31 个状态在严格 G 库中
连候选都没有。核对原始 86,984 条连续记录后确认：95/95 个状态都有至少一次同 K 的出手后局面，
且所有记录都满足 `K<8: S_k -> S_(k+1)`、`K=8: -> END`；不存在跨 K 边。

新增 `build_universal_semantic_goal_mdp_v1.py`，把层次修正为：

```text
S_k
  -> G_k = (K, 放/清类型, 双方营内壶数变化, 清除数, post-own 控分/宏观形态)
  -> P(S_(k+1) | S_k, G_k)
  -> 可选的 exact post-own topology / 细终点圆 / 动态清壶绑定
```

完整精细 post-own topology 不再直接充当语义 G 的 ID；否则会产生 30,049 个微小结果。压缩后的
v2 语义边表有 4,514 个源状态条件目标，运行时每个 S 只返回按 K8→K1 历史倒推排序的主 G 和最多
两个结果不同的备选。`nwnht_v2_universal_semantic_goal_mdp_v2.json` 覆盖 95/95 个状态：74 个主 G
在五个按比赛留出折中保持首选，21 个有部分跨折支持；每条返回边都保存下一状态分布。

87 个主 G 有历史细实现子项，8 个没有可绑定的细实现；后二者仍是明确的战术 G，但**不可直接送给
PhysX**。严格精细 G 库的 30 个目标因此改为执行子层，而不再错误地决定状态机是否有边。新增
`runtime_semantic_goal_mdp_v1.py` 对外提供 `load_semantic_goal_mdp()`；它在镜像还原后返回同 K 的
G 和 `S_(k+1)` 分布，调用方必须在对手回应后读取真实棋盘重新分类。

### 9.20 当前棋盘 GoalContract 实例化与回放验收（2026-07-18）

新增 `semantic_goal_contract.py`，输入当前规范坐标棋盘与运行时选中的 `G_k`，输出最多三个
`GoalContract`：当前对方营内壶组合的动态出界绑定、出手壶历史细圆、语义营内变化/控分验收条件、
允许的精细 post-own 拓扑分布和 `P(S_(k+1)|S_k,G_k)`。`opponent_house_removed_count` 被正确解释为
营内占位变化：只有它与总出界数的交集才要求具体壶出界；被撞出营但仍在场的壶不能被错判为出界。

`audit_semantic_goal_contract_replay_v1.py` 对每个状态全数据主 G 的历史实现做回放：18,741 条匹配记录
的语义合同验收率为 100%，99.42% 能在原始出手前盘面绑定至少一个细合同。该审计证明的是“棋谱差分
→ G → 合同”的编译一致性，不是因果胜率或 PhysX 可达性。

细圆覆盖同批具有唯一新增出手壶记录的比例仅为 15.78%。原因是同一语义 G 下仍有多峰精细实现，当前
接口只保留三个最高支持细圆；因此细圆只能作为当前可尝试的初始合同，不应假装覆盖该 G 的全部实现。
下一阶段若要扩大精细执行覆盖，应以当前精确盘面检索相似历史 `B_k -> U_k` 实现后再选圆，而不是扩大圆
或降低验收门。

### 9.21 条件化精细落点检索（2026-07-18）

新增 `build_contextual_fine_exemplars_v1.py`，为 95 个当前主 `S_k -> G_k` 边保存 18,741 条
历史 `B_k -> U_k` 实现（其中 16,586 条有可唯一识别的出手壶终点）。运行时
`ContextualFineRetriever` 只在同一 `(S_k,G_k)` 内，以双方壶坐标的同色对称最近距离检索最多 20 条
相似出手前棋盘；在这些端点中以 0.35m 连续空间密度簇输出至多三个圆。左右镜像在检索前归一、输出前还原。

`audit_contextual_fine_retrieval_v1.py` 以比赛为整体留出：每个查询排除自己的整场比赛，并对每个状态最多
取 50 个不同比赛的主动终点。3,432 个留出查询中，3,420/3,432 = 99.65% 能得到细圆；
相似检索圆覆盖真实终点 1,220/3,432 = **35.55%**，同一批查询的全局三个细圆仅 475/3,432 = **13.84%**。
早期 0.25m 网格检索仅 11.19%，已拒绝，不进入运行时。该改进说明当前精确棋盘确实影响细实现，但它仍仅是
历史终点覆盖验证；不改变 G 的价值排序、不读取比赛上下文，也不替代路径/碰撞验证。

### 9.22 上下文放置合同的严格 PhysX 闭环（2026-07-18）

新增独立的 `semantic_contract_physx_bridge.py`；它不改旧策略、旧状态机或旧求解器。对满足
“对方出界数为 0 + 有上下文主动壶圆”的合同，桥接层把规范坐标棋盘转换为本地 PhysX 坐标，调用既有
粗代理→严格 PhysX→Newton/MADS，并把每个摩擦种子的完整终局棋盘转回规范坐标。只有当全部种子同时满足：

```text
出手壶在合同圆内
AND 本地自由防守区规则合法
AND 绑定的出界要求成立
AND 合同的 G_k（双方营内变化、对方总出界、控分、宏观形态）成立
```

才返回 `CERTIFIED_SEMANTIC_CONTRACT`。这比旧的“落进圆即成功”多了完整 G 的终局验收；相反，圆命中但
G 不成立会返回 `REJECTED_BY_STRICT_SEMANTIC_CONTRACT`。清壶/滚位/双飞合同明确返回
`UNSUPPORTED_NONPLACEMENT_CONTRACT`，不会被伪装成 draw。

K1 空盘主 G 的一次三种子、8 秒小预算烟雾测试没有在第一个上下文圆中找到路线，返回
`NOT_FOUND_WITHIN_CURRENT_SEARCH_BUDGET`，其余圆因总预算耗尽未尝试。这是求解器当前预算下的阴性结果，
**不是**数据 G 错误、更不是 PhysX 不可达证明；它正好说明状态机和可达性层已被正确分离。下一步应在固定的
少量代表性合同上单独调参/加初值覆盖，再做独立的碰撞合同终局验证，不以扩大采样来掩盖问题。

同一 G 的不同上下文细圆现可由 `solve_semantic_placement_contracts_parallel()` 并行执行：每个候选使用一个
独立 `spawn` 进程、独立粗代理和独立 PhysX 场景，先大范围粗筛、再 Newton/MADS。worker 尝试绑定一个 CPU
核心并限制 OMP/OpenBLAS/MKL 为单线程，避免多进程时内部数值库再次满核。每个候选拥有自己的搜索预算，结果按
原始细圆优先级重新排序；只在回收结果中选择最高优先级的 `CERTIFIED_SEMANTIC_CONTRACT`，不让并行完成顺序
篡改数据 MDP 的 G 排序。

### 9.23 PhysX 可执行性口径收紧与本地 PPO 接入（2026-07-18）

发现原始模板中有 755/86,984 条记录的 `opponent_removed_count < 0`。我方本手不能生成对方新壶，因此这是
跨帧/面板对齐异常而不是可执行战术结果。构建器现在在语义聚合前剔除它们，生成
`nwnht_v2_universal_semantic_goal_mdp_v3_physx_admissible.json` 与对应上下文样本库
`nwnht_v2_contextual_fine_exemplars_v2_physx_admissible.json`；95 个状态仍全有 G，且主 G 中不再存在负清除数。

放置、单清和双飞均收敛到同一严格验收：所有摩擦种子必须满足本地 FGZ、绑定目标实际出界（适用时）、
主动壶区域（适用时）和语义 `G_k` 的双方营内变化/控场/宏观形态。单清与双飞的碰撞拓扑仍由粗代理选父分支、
再由 PhysX MADS 细化，不能被 draw 代替。K8 在此之后还须对每条己方终局跑有限对手末壶反击筛查；有反例即拒绝，
无反例只是固定预算下“暂未发现反例”。

`SemanticTacticalMatchPlayer` 作为评测适配层接入 `evaluate_vs_teammate_ppo.py` 的
`--semantic-tactical-library` 开关：先手合同获认证才出手，否则逐手回退未改动的旧规划器。相同种子
20260718、代理先手、3 PhysX 种子、旧规划器每手 6 秒的一局 PPO 基线为 -1；语义合同每候选仅 2 秒时同为 -1，
8 次语义尝试均未认证、全部回退，运行时由 38.0 秒变为 58.1 秒。这是集成/回退正确性的证据，不是策略提升或失败的
胜率结论；K1 同一上下文圆在 15 秒、3 种子下已能被严格认证，说明下一轮 PPO 对比必须给予合同足够预算。

随后以相同种子、相同 PPO、先手代理、合同仅取最高优先级一个、每合同 15 秒/3 摩擦种子完成一局（拆为 4 段，
每段从前段严格终局 `x/y/yaw` 和真实 shot slot 无损恢复）：8 次先手中 3 次
`CERTIFIED_SEMANTIC_CONTRACT`，其余回退。终局语义组为 **-2**，旧规划器基线为 **-1**，两者均负于 PPO。
因此目前唯一诚实结论是：该小样本里语义执行层未提升，且多失 1 分；样本量为一局，不能推为胜率，但已足以否定
“物理认证的历史目标自然优于旧策略”的假设。后续改进应检查 G 的排序/终点检索与本地规则动力学之间的域差，
不能只提高 PhysX 搜索预算。

### 9.24 K1 固定中线守壶后的本地 No-Tick 裁剪（2026-07-18）

K1 空场不再按历史均值在“营内占位”和“中线守壶”间选择；运行时直接使用经空场严格 PhysX 标定的
`OPENING_CENTRE_GUARD_SHOT=(2.739,-0.0243,0)`，目标为本地 `(2.375,7.15)`。这使 K2 的前置条件变为：
我方 K1 锚点守壶仍在自由防守区并触及中线。前五壶中，任何使该壶离开中线或自由防守区的对手出手均按本地
模拟器规则回滚。

新增 `build_local_k1_anchor_k2_subset_v1.py`，不覆盖 95 状态通用库。它从历史 K1 中线守壶样本中仅保留
对手回应后锚点仍满足上述条件的记录。初版曾把历史守壶纵向位置限定为固定本地目标附近 ±0.30m，错误地把
罕见分支压缩到 5/6 条；现已取消该硬筛选，改为逐样本保留相对本地目标的纵向偏移，供后续近邻检索加权。
全部 2,537 条历史 K1 中线守壶中，2,186 条保留，351 条 `No-Tick` 冲突记录排除。保留记录聚成五个 K2 条件
状态：锚点独存（279）、锚点+对手营内壶（1,301）、锚点+对手侧守壶（553）、锚点+对手中线守壶（28）、
锚点+对手其他在场壶（25）。

工件 `nwnht_local_k1_anchor_k2_subset_v3.json` 是**规则兼容的 K1→K2 历史回应证据**，不是新的部署策略；
下一步必须只从这些带锚点 `S2` 中重新提取/评分 `G2`。被排除的 351 条不应被伪造为“对手会 pass”的证据，
也不能继续参与固定 K1 守壶后的转移概率。

随后由 `build_local_k1_anchor_k2_goals_v1.py` 沿这 2,186 条保留轨迹读取实际 K2 出手；7 条不可能的对方壶
生成记录被再次剔除，余下 2,179 条成为条件 G2 证据。排名只在同一带锚点 S2 内做直接终局分差的五条收缩，
不借用旧的无条件 K2 排名，也不称作因果/极小极大值。为避免支持为 1 或 4 的偶然结果被部署，最低直接支持
设为 30：五个 S2 中三类有可用 G2（锚点独存 2 个、对手营内壶 3 个、对手侧守壶 3 个），对手中线守壶与
“其他在场壶”两类均明确标为 `SEARCH_REQUIRED_LOW_CONDITIONAL_SUPPORT`。产物为
`nwnht_local_k1_anchor_k2_goals_v5.json`；它尚未接入运行时，必须先审查每个 G2 的战术含义和精细区域，再决定
是否作为 K2 专用覆盖层。

## 10. 明确不做的事

- 不从“胜局”筛样本再聚类；状态和失败局面必须保留；
- 不把 47、95 或任意状态数当目标；状态数由支持度和后继差异决定；
- 不把历史上常见的清壶当默认攻击策略；
- 不把中线守壶或三角侧壳称为绝对安全构型；
- 不做 PDF 坐标提取，不覆盖已有数据；
- 不改 `planning_proxy/first_player_strategy.py` 或旧提交策略；
- 不在战术价值排序前调用 PhysX；
- 不把“代码能跑”或“历史均值高”写成“策略已证明能赢”。
