# v2 碰撞终局契约审计

## 结论

碰撞动作现在不再是“看见敌壶就清”的隐式指令。它们以独立数据契约表达：

```text
源状态 S
  + 父动作 A（移出数量、出手壶语义落区）
  + 当前棋盘上的目标壶几何角色绑定
  -> 指定 target slot 必须 OUT_OF_PLAY
  + 出手壶必须进入某个落区子圆
```

`build_collision_goal_contracts_v1.py` 从既有 v2 父动作和其细目标的匿名壶
绑定中抽取契约，输出
`artifacts/nwnht_v2_collision_goal_contracts_v1.json`。

## 数据结果

在“父动作支持至少 30、保留细目标中同一种绑定占至少 80%”的门槛下：

| 项目 | 数量 |
| --- | ---: |
| 历史移出对方壶父动作 | 160 |
| 可形成单目标碰撞契约 | 115 |
| 拒绝 | 45 |
| 双飞/多壶契约 | 0 |

115 条全部是 `SINGLE_OPPONENT_REMOVAL`，目标绑定均为“当前营内对方壶集合中
选择一颗；按距按钮最近优先”。这不是历史壶 ID；NWNHT 同色壶跨帧没有可靠
身份，因此运行时只允许几何角色绑定。

拒绝原因包括：没有可表达的出手壶滚位区域、细目标绑定不占主导、以及“要移出
数量”和“可绑定目标数量”不一致。拒绝的动作不会被弱化成单清或无约束撞击。

## MADS 桥接与严格语义

`physx_goal_bridge.py` 新增：

- `bind_contract_for_runtime_state(...)`：先重新做 v2 状态判定，状态不匹配不绑定；
  若本地壶面是规范坐标的左右镜像，先翻回语义区域再生成小圆；
- `bind_single_collision_contract(...)`：将当前目标壶 slot 和区域小圆组合成有序请求；
- `solve_single_collision_requests(...)`：调用现有
  `粗代理 -> 严格 PhysX -> MADS` 单目标碰撞链。

旧 MADS 的 `physical_clear` 也容许把目标推去战术废球带；v2 契约写的是
`OUT_OF_PLAY`。因此桥接器在 MADS 返回后还会逐条 PhysX 摩擦序列检查目标 slot
确实 `enabled=false`，废球带不算契约成功。

## 一条真实历史前态的受限冒烟

选取契约 `...e017a86fa981a233:collision:fbf7dc71bae8` 的原始样例 `97:3`：

```text
K2_V2_FIRST_HOUSE_CONTROL_3
己方：按钮附近一壶
对方：一颗营内壶
要求：绑定该当前对方 slot，实际出界；出手壶进入镜像恢复后的前营扇区
```

将其重新分类，得到同一源状态，且该局面确实为左右镜像；适配器正确把扇区
恢复到调用方一侧。之后以 1 条摩擦序列、30 秒预算调用单目标 MADS：

```text
粗代理覆盖：7 x 41 x 15 = 4305 条初值
结果：NOT_FOUND_WITHIN_BUDGET
```

这只说明**当前**粗代理覆盖、单目标 MADS 与预算没有产出经过认证的路线；不说明
该历史动作物理无解，更不允许因此转成“清任意壶”的攻击回退。该契约目前也没有
通过运行时父动作跨折共识门，因此这个冒烟仅验证碰撞接口与失败语义，不是正式
策略推荐。
