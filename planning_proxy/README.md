# 白盒规划代理

这个目录用于开发“**快速筛路线，严格 PhysX 定最终球**”的战术规划代理。

它不是 `local_simulator/` 的替代品，也不能直接把代理结果发送给比赛服务器。当前严格模拟器仍是唯一的最终物理裁决器；代理只负责在单核、有限时间内，从大量候选出手中筛出少量值得严格计算的球。

当前范围：非扫冰；一手规划；优先清出敌方壶，同时优先保证场上**所有己方壶（包括本次出手壶）**都不出界；在同一安全档的可提交路线中，优先留下更多己方得分壶在大本营内。

多手对局时，规划器会把场上每颗旧壶的真实位置、PhysX slot 和 yaw 一并带入严格回放；本次新出手壶仍按 factory yaw=0 起步。不要把已有壶重新编号后再回放，否则会丢失 PhysX 的壶身份，导致碰撞结果偏离真实对局。

## 快速开始

必须使用随本项目交付的 Python 3.8 运行时：

```powershell
$py = 'D:\esp\tmp\curling_pyphysx_conda\python.exe'

# 第一步：对当前局面快速筛选连续的 v0 / h0 / w0 区域。
# 未传 --board 时仅使用内置的三壶演示局面。
& $py planning_proxy\run_analytic_proxy.py `
  --board your_board.json `
  --shot-index 7 `
  --output planning_proxy\runs\coarse.json

# 第二步：严格 PhysX 复核。每个区域最多 27 个小扰动，默认三条摩擦序列；
# 如果已找到“所有敌壶均出界、所有己方壶与出手壶均留下”的球，会自动提前停止。
& $py planning_proxy\strict_refine.py `
  --proxy-report planning_proxy\runs\coarse.json `
  --output planning_proxy\runs\strict.json
```

`your_board.json` 是静止壶数组；slot `0` 留给出手壶，已有壶只能用 `1..15`：

```json
[
  {"index": 1, "owner": "opponent", "x": 2.55, "y": 5.45},
  {"index": 2, "owner": "self", "x": 2.05, "y": 7.25}
]
```

最终只取 `strict.json` 里第一名的 `bestshot`；`coarse.json` 不能直接提交。

严格层按三个档位依次选球：先要求 **0 颗己方壶出界**；完全没有可提交球时才允许 **1 颗**；还没有才允许 **2 颗**。出手壶和场上原有己方壶完全同等，都计入这个数量。一旦低档存在候选，就不会使用高档。无论在哪一档，规则都不能违规，而且每一条摩擦序列里必须满足：`己方实际出界总数 <= 敌方实际出界数`。这里的“清走/出界”只认严格 PhysX 最终的 `enabled=false`；只是撞动、挤出大本营、但仍留在场内，均不计数。

同一档中，候选先按“最差一条摩擦序列里己方仍在大本营的壶数”排序，再按三条序列的平均数量排序；只有这两项相同，才比较原有的清敌收益。换句话说，系统不会为了堆壶而接受犯规、漏清目标或更多己方出界，但两条路线都同样安全时，会选能留下更多得分壶的那条。

若必须清掉指定敌壶，在两步命令都额外传入 `--must-clear-index <slot>`。它要求该 slot 在每一条摩擦序列的最终状态中都实际出界；“不再得分”不能替代“已清出界”。报告的 `selectionMode` 会明确写出 `full_preserve`、`1_own_out_trade`、`2_own_out_trade` 或 `no_submit_candidate`。

唯一的例外是**最后一局后手**且开局场上只有一颗敌壶：严格复核命令可再加 `--last-end-hammer-closer-win`。此时不再要求目标敌壶出界，也不再按“己方出界数不超过敌方出界数”限制；每条摩擦序列的最终局面只需同时满足：场上剩余己方壶数**严格大于**敌方壶数，且敌壶仍在场时，它到大本营中心的距离严格大于己方最近壶的距离。相等不算赢；本次出手壶同样按最终是否在场计数。该开关会拒绝“场上有多颗敌壶”的局面，避免误用；自由防守区犯规仍然一票否决。

`--shot-index` 是本局的零基投壶序号：第 1–5 次投壶填 `0..4`，第 6 次填 `5`。它不能省略，因为前五手需要执行自由防守区规则过滤。

## 先手中线控场模式

先手方使用偶数全局投壶序号 `0, 2, ..., 14`。在粗筛命令追加
`--first-player` 后，规划器会把本轮策略写入报告，严格 PhysX 读取同一份
报告并据此排序：

```powershell
# 我方先手的第七颗（全局第 13 次投壶）。
# 状态机先判断：最近壶、第二红圈壶、前方保护壶，哪一层被对手拆掉。
& $py planning_proxy\run_analytic_proxy.py `
  --board current_board.json --shot-index 12 --first-player `
  --output planning_proxy\runs\first_player_coarse.json

& $py planning_proxy\strict_refine.py `
  --proxy-report planning_proxy\runs\first_player_coarse.json `
  --output planning_proxy\runs\first_player_strict.json
```

它对应的规则是：第一颗占中线；第二、三颗建立错层红圈壶；第六颗起先处理对方
上一颗仍有效的壶，再按我方当前在场壶数提供多个可替代的防御形。只有一颗己方壶时，
搜索“双红圈错层、左护门、右护门”；两颗时搜索“左三角、右三角、第三红圈错层”；
三颗及以上时搜索“左外壳、右外壳、红圈后备”。这些是“或”关系，不是必须依次完成。
这不是固定坐标脚本：目标点只用于吸引搜索，最终是否真的清壶、进红圈、保住己方壶，
都仍由每条摩擦序列下的严格 PhysX 终局决定。

## 当前实测状态

- 粗筛使用随目录交付的 14×10 白盒受力表；它由已恢复的自由滑行公式离线计算，不是训练出的模型。首次部署不需要现场建表。
- 默认使用加密粗筛：**4305** 条首轮路线（7×41×15）加本构型的 **16065** 条局部连续候选，实测为 **6.06 秒**（单核）。可用 `--coarse-velocity-count`、`--coarse-lateral-count`、`--coarse-spin-count` 按时间预算继续调整。
- 同一构型下，严格层最多精修前 3 个区域，81 条局部候选 × 3 条摩擦序列为 **37.70 秒**；端到端约 **44 秒**，三条序列均清敌、零己方出界，并命中防御形之一。
- 在 20 个非空的固定残局构型中，以恢复的逐 0.01 秒自由滑行公式为对照，45 cm 风险通道保住了 **205/205** 条“会先撞敌方”的测试路线；同时只送 280/1200 条进入后续严格复核。报告见 `runs/analytic_proxy_fixture_audit_force_lookup_compact.json`。
- 演示三壶局面：粗筛 3.27 秒，严格层第一个局部区域的 27 候选 × 3 条摩擦序列为 6.89 秒；找到稳定双清后提前停止，总计约 10 秒。

这些数字证明的是“自由滑行阶段不漏可撞敌路径”的筛选能力。碰撞链、被撞壶终局和最后提交仍完全由严格 PhysX 决定。

## 比赛规则过滤

严格层会执行本地 `比赛细则.md` 中会撤销一手的自由防守区规则：

- 仅在本局第 1–5 次投壶（`shot-index=0..4`）启用；
- 对方自由防守区壶不能被直接或间接撞至无效位置；
- 对方位于自由防守区、且触及中线的守壶，不能被撞离中线或撞离自由防守区；
- 任一摩擦序列触发上述情况，候选都不输出为可提交 `BESTSHOT`。

规则不是等到最后才看：前五手里，粗代理会把“预计首撞对方自由防守区壶”的路线降到末位；严格 PhysX 再检查真实的直接/间接碰撞终局。前者省时间，后者负责最终不犯规。

可用下面的回归命令复跑空场、单/双/三清、己方挡路、窄通道、多壶营内、前五手单/双守壶、第六手清中线守壶、十壶复杂局面共 12 类构型：

```powershell
& $py planning_proxy\validate_rule_and_safety_scenarios.py
```

当前基准结果为 **12/12**：每类均找到至少一组在三条摩擦序列下规则合法、所有已有己方壶与出手壶均留在场内的参数。完整记录见 `runs/rule_and_safety_scenarios_v1.json`。这是一套安全回归，不代表已经证明每类局面下的战术得分最优。

其余细则中“收到 `GO` 后 2 分钟内必须回复 `BESTSHOT`、每局八手、按大本营计分”等内容属于比赛流程或策略输入，不是某一组出手参数的物理犯规；它们不应伪装成物理过滤条件。中线犯规后的 `CENTERLINE_CHOICE` 是独立的短时回复流程，正式 DCP 路径约 5 秒，超时默认 `KEEP`。

实施方案见 [白盒规划代理实施方案](01_白盒规划代理实施方案.md)。

当前讨论形成的先手控场路线、战略出界定义、前五次投壶布局和第六颗后的防御壶型，见[中线控场与残局防御策略](03_中线控场与残局防御策略.md)。这是一份策略与实现规格；它不会绕过本文的严格 PhysX 最终复核。

最后一手的防御形、候选如何搜索、何时算真正补齐防线，以及对手末手如何反证，见[防御形搜索与验收规则](04_防御形搜索与验收规则.md)。其中明确区分了“过渡球形”和当前唯一通过较强反证的“中心锚 + 中线守壶 + 左右双门”。

公开顶尖队伍的真实比赛布局如何转成离散目标树，见 [Team Gushue 公开战术树（证据版）](05_Team_Gushue公开战术树_证据版.md)。它只整理有公开来源支持的比赛行为；没有把未公开的内部战术伪装成事实。

末手防线不能只凭摆盘判断。下面的命令会让对方最后一颗同时搜索直进/旋进和
先撞守壶的路线；若对方进入按钮区或比我方最近壶更靠中心，就把该球形判为失败：

```powershell
& $py planning_proxy\validate_final_defence.py `
  --fixture "中心锚加双门" `
  --direct-parents 3 `
  --impact-parents 3 `
  --physics-seeds 9
```

当前 162 条严格反击候选 × 9 条摩擦序列的筛查中，只有“中心锚 + 中线守壶 +
左右双门”暂未发现反例；它仍是有限搜索下的候选，而非数学上的无敌证明。

## 一句话流程

```text
读取局面 → 白盒粗代理筛数千条路线 → 严格 PhysX 按区域精修并多随机序列复核 → 提交一组 BESTSHOT
```

## 运行边界

- 代理不能替代 Unity/严格 PhysX 的物理结论。
- 最后一轮必须使用严格 PhysX，且对前几名候选按多条摩擦随机序列复核。
- 扫冰暂不进入代理或最终决策。
- `assets/recovered_formula_force_lookup_compact_v1.npz` 是运行必需资产；仅当恢复公式或基础摩擦常数变更时，用 `build_force_lookup_asset.py` 重新生成它。
