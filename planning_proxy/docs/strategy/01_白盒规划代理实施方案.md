# 白盒规划代理实施方案

## 1. 要解决什么问题

当前严格本地模拟器已经比 Unity 快，但一组 `BESTSHOT(v0, h0, w0)` 仍需完整推进自由滑行、碰撞、碰后静止和出界清理。若把数百组候选全部严格计算，单核耗时会累积到数十秒甚至更长。

比赛服务器的总时限是 2 分钟。本方案的工程目标不是让代理替代物理真值，而是在**单核 CPU 下尽量于 60 秒内**完成一手规划：

1. 尽可能让敌方壶出比赛区；
2. 优先将所有己方壶（包括出手壶）留在比赛区；若做不到，按 0→1→2 颗己方壶实际出界逐档放宽，且每条摩擦序列中己方实际出界数不得超过敌方实际出界数；
3. 用严格 PhysX 复核最终候选后，才输出一组 `BESTSHOT`。

这里的“全部创飞”是攻击型评分目标，不是每个局面的唯一目标。例如己方已经在大本营得分时，清走己方壶通常是坏结果；代理必须把己方损失设为更高代价。

## 2. 关键决定

### 2.1 不训练黑箱神经网络作为第一版

第一版采用可解释的白盒代理，而非端到端拟合完整 PhysX：

- 已知的旋球自由滑行公式直接复用；
- 壶近似为二维圆盘；
- 碰撞近似为动量交换和切向摩擦；
- 每次只处理“出手、首次接触、后续接触、出界、静止”这些事件。

这样每一条路线为什么被筛掉都可解释：撞到己方、未命中敌方、传力链不朝边界、或预测会让出手壶出界。

以后若白盒代理在复杂多碰撞下排序不足，可额外训练小型的“碰撞修正器”；但它只能修正白盒结果，不能取代严格 PhysX。

### 2.2 代理只负责排序，不负责最终提交

代理输出候选的粗略排序和风险标签。严格 PhysX 对前 `K` 个候选逐一复核，最终提交严格结果最优的那一组。这样代理即使有厘米级甚至更大的终点误差，也不会直接污染最终出手。

### 2.3 当前只做非扫冰

扫冰的协议时机和物理效果尚不在严格交付范围。代理和精修阶段都固定为 `sweep=0`，以免把未验证机制引入决策。

## 3. 输入、输出与评分

### 3.1 输入局面

每一手接收：

- 16 个 stone slot 的 `enabled / x / y / yaw`；
- 每颗壶的阵营（由 slot 奇偶和当前先后手推得）；
- 当前出手方、手数、是否后手；
- 当前策略目标，例如“清敌方”“保护己方得分壶”“把某颗敌壶推向边界”。

第一版假设所有在场壶均已静止，这是正常回合之间的条件。

### 3.2 输出

代理对每组参数输出：

- `v0 / h0 / w0`；
- 预计首个接触对象和碰撞链；
- 预计敌方出界数、己方出界数、出手壶是否出界；
- 预计终局得分变化与风险分；
- 是否进入严格 PhysX 复核队列。

最终对服务器只输出一条严格验证过的：

```text
BESTSHOT v0 h0 w0
```

### 3.3 攻击型评分

第一版使用可配置的局面评分，而非固定的“只看击飞数”：

```text
总分 = 敌方出界奖励
     - 己方出界惩罚（粗筛排序用）
     - 出手壶出界惩罚（粗筛排序用）
     + 敌方移出大本营奖励
     + 己方留在大本营/得分区奖励
     - 不确定性风险惩罚
```

粗筛阶段仍用惩罚项排序；严格 PhysX 阶段按 0→1→2 颗己方壶实际出界逐档选择，出手壶与原有己方壶同等计数，只有规则违规始终直接剔除。这里“出界”只认严格终局的 `enabled=false`：撞动、移出大本营但仍在场内都不算清壶或换壶。具体粗筛权重由固定局面集上的严格 PhysX 结果标定，而不是拍脑袋固定。

## 4. 白盒代理的物理结构

### 4.1 自由滑行层：复用已恢复的旋球机制

出手壶尚未撞壶时，不重新发明曲线：直接使用已经恢复的 `CurlingMotion.Newfrictionstep` 规律，但**不在每个 `0.01 s` tick 调用 PhysX**。当前实现将该公式离线采样为 14×10 的“速度 × 绝对旋转量”白盒受力表，运行时双线性插值推进；代理自己推进自由滑行状态，并采用以下方式：

- 用 `0.02 s` 的代理步长推进速度、旋转和位置；
- 每段轨迹按“扫掠圆盘”而不是只看离散点判断是否会擦到壶，避免从两颗壶之间漏检；
- 只要该段距任一壶进入风险带，自动把该局部细化回 `0.01 s` 代理步长；
- 在 `v0 / h0 / w0` 的**连续小区域**上做自适应细分，而不是依赖一张固定 1000 条路径表。

代理步长和公式近似都要按严格 PhysX 的首撞对象、接触点和接触前速度单独标定。它回答的是：从左还是从右绕、最先可能撞谁、是否会先撞己方壶、哪一小块参数区域值得精修；它不负责给出毫米级终点。

### 4.2 事件层：二维圆盘碰撞链（后续，不是当前实现）

代理把每颗壶看作圆盘。检测到接触时：

1. 计算接触法线和切线；
2. 按等质量动量交换、恢复系数、切向摩擦估计碰后速度；
3. 将各壶重新放入滑行层；
4. 继续寻找下一次接触或出界。

当前版本在首次可能接触时停止，把碰撞链完全交给严格 PhysX。二维圆盘碰撞链仍是未来可选的排序层；在它通过严格 PhysX 批量对照前，不把它用于最终决策。

### 4.3 终局层：边界与局面评分

每个事件后检查严格模拟器使用的比赛区边界：

```text
x ∈ (0.145, 4.605)
y ∈ (2.865, 10.525)
```

越界即标记为出界。代理还会计算大本营内壶的相对距离，以便对“敌方清出界”和“敌方被赶出得分区”给出不同评分。

## 5. 候选如何生成

不能在完整参数立方体里盲目随机试十万组。候选应由局面几何产生：

1. **单清候选**：对每颗敌壶生成正碰、左切、右切三类线路；
2. **双清候选**：寻找两颗敌壶是否接近共线，且传力方向是否指向边界；
3. **边界候选**：对靠边敌壶生成将其推向最近边界的入射方向；
4. **绕己方候选**：用旋球路径绕开己方壶后从侧面进入；
5. **保壶候选**：若己方处于有利得分位置，生成不接触己方的进攻路线。

每一类只生成有限的命中点、速度和旋转扰动。代理可在这些候选周围做小范围局部扰动，而不是全局盲搜。

## 6. 单核时间预算

下表是设计预算，必须通过基准测试验证，不能当作既成事实。

| 阶段 | 预算 | 说明 |
| --- | ---: | --- |
| 读取局面、生成战术目标 | < 1 s | 只读协议状态。 |
| 几何生成 2,000–10,000 个候选 | < 3 s | 基于敌壶、己方壶和边界。 |
| 白盒路径与碰撞链排序 | 5–20 s | 单核；先以 NumPy/紧凑 Python 实现并实测。 |
| 选出前 8–16 条路线 | < 1 s | 追加风险过滤。 |
| 严格 PhysX 复核 | 15–35 s | 每条候选使用多条摩擦随机序列。 |
| 最终选球与协议发送 | < 1 s | 只发一组 BESTSHOT。 |
| **目标总计** | **≤ 60 s** | 留出服务器和异常缓冲，硬上限为 120 s。 |

若 Python 实现无法达到代理阶段 20 秒以内，再把事件循环移入现有本地原生扩展；不应降低最终严格 PhysX 的复核数量来伪造加速。

## 7. 随机性与风险控制

同一 `BESTSHOT` 在不同冰面摩擦随机序列下可能有不同终局。代理阶段可以使用平均摩擦或少量廉价扰动；严格阶段必须：

1. 对前 `K` 组候选用多个 `physics seed` 重跑；
2. 统计敌方清出数、己方损失和终局得分的分布；
3. 用保守分数排序，例如优先比较较差分位数，而不是只看最好一次；
4. 把偶然连撞成功但成功率很低的候选降级。

## 8. 验收不是终点 RMSE

规划代理的终点不需要毫米级；验收重点是它是否替严格搜索节省时间而不漏掉好球。

| 指标 | 初始验收目标 |
| --- | --- |
| 代理正确识别“首撞己方”的比例 | 在代表性局面集上单独统计。 |
| 严格 PhysX 最优球进入代理前 12 名的比例 | 作为核心排序召回率，按局面类型分别报告。 |
| 代理前 12 名经严格复核后的最优分数 | 与全严格搜索基线比较。 |
| 单核端到端 P90 耗时 | 目标 ≤ 60 s，硬上限 < 120 s。 |
| 最终球 | 必须来自严格 PhysX 多随机序列复核。 |

任何只报告“代理自身终点误差”的实验都不能证明它适合规划。

## 9. 实施阶段

### P0：固定基准与评分定义

- 建立多壶代表性局面：单清、双清、敌方靠边、己方夹在中间、己方已得分、最后一壶。
- 固定阵营、目标、随机种子和严格搜索预算。
- 记录全严格搜索的耗时和最优结果，作为后续比较基线。

### P1：无碰撞数学代理（已实现并完成首撞筛选审计）

- 实现不调用完整 PhysX 场景的自由滑行推进：14×10 白盒受力表 + `0.02 s` 积分；直球是 `w=0` 的普通特例。
- 对每一段路径做扫掠圆盘相交检测，而不是靠固定离散路径点或固定 1000 条轨迹表。
- 在连续参数区域上自适应细分，输出“安全绕行区 / 首撞敌方区 / 首撞己方区 / 出界区”。
- 已在 20 个非空固定残局中，对 1200 条连续样本验证：45 cm 风险通道保住 205/205 条恢复公式判定的“首撞敌方”路线。只做筛除，不做碰撞后终局预测。

### P2：一撞与多撞圆盘事件代理

- 加入二维冲量、切向摩擦和重复接触检测。
- 输出接触链与粗略出界预测。
- 用严格 PhysX 标定少量透明参数。

### P3：候选生成与严格精修调度（第一版已实现）

- 将单清、双清、边界和绕己方候选统一排序。
- 让严格 PhysX 在每个粗筛区域的 3×3×3 小盒内、多条摩擦序列复核；若已经达到“所有敌壶均出界、己方与出手壶均留下”的理论满分，提前停止。
- 输出一个带成功率和风险说明的最终 BESTSHOT。

### P4：单核时间与质量验收

- 在固定代表性局面上跑端到端基准。
- 报告每阶段耗时、严格最优召回率、最终分数损失和失败案例。
- 若不能在预算内达到足够召回率，优先改候选生成和碰撞链参数，不急于引入神经网络。

## 10. 明确不做的事

- 不把白盒代理伪装成 Unity 对齐模拟器；
- 不在最终提交时跳过严格 PhysX；
- 不把扫冰加入当前结论；
- 不用一次幸运随机摩擦结果证明一条多清路线可靠；
- 不将“清空所有敌壶”写成不考虑比分和后手的绝对规则。

## 11. 当前下一步

下一步是在 24 个固定残局上做端到端审计：对每个局面记录粗筛保留的区域、严格 PhysX 实际最优球是否进入这些区域、最终分数与全严格搜索基线的差异、以及单核 P90 耗时。当前 `205/205` 只验证“首次可能撞敌方的路线不漏”，还不能替代这项碰撞终局验收。

已完成一套独立的 12 类规则/安全回归：空场、单/双/三清、己方挡路、窄通道、多壶营内、前五手单/双守壶、第六手清中线守壶、十壶复杂局面。每类均在三条摩擦序列下找到规则合法且全保己方的候选；该结果用于防回归，不代替 24 个残局的战术最优性审计。
