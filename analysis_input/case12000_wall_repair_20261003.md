# 12000 墙碰撞及停用路径已补齐

原首次分叉已消除：本地真实 `bound1` 接触在第1879步产生进入事件，执行已确认的 `OnCollisionEnter(Wall)` 行为。没有注入帧号、Unity 位姿、清理调用或位置阈值。

## 实现依据与改动

1. 从原始 `unity_data_20261002.unity3d` 的 `level4 / GameSceneNoLimit` 读取四块 Wall 的 BoxCollider、Transform、标签和 PhysicsManager 接触偏移。运行捕获命令使用 `--auto-infinite-ui`。资源的 binary32 数值直接保存到 `local_simulator/assets/unity_wall_colliders.json`，不使用库存文本中截断的小数。墙的空材质引用走原始 `f73733` 默认分支，静/动态摩擦0.6、恢复系数0。
2. 原模拟器只建立冰面和冰壶，现加入实际静态墙。反汇编还确认绑定的接触过滤器只为两边都是动态刚体的碰撞开启通知：CP39 的函数入口RVA `0x25cc0`，动态类型检查在 `0x25d23`、`0x25d2b`，通知位写入 `0x21c`。因此仅加入墙体仍不能收到回调。
3. `native_wall_contact.py` 给墙的过滤数据加本地标签，并为这些形状开启相同的进入/持续/离开/接触点通知。该标签只是本地事件上报的标识，不声称 Unity 使用同一标记。保留原过滤函数和动态壶对壶的接触修改分支，不给静态墙开启摩擦修改。仅在已验证哈希及原始指令吻合时安装内存转发；磁盘上的原生绑定没有修改。
4. `_simulate_unity_step()` 收到真正的 `eNOTIFY_TOUCH_FOUND` 后，按实测 `f61030 → f54405 → f71727` 顺序恢复摩擦、清零线/角速度、保留碰撞姿态并停用 RigidSim。实际 `SetActive` 链中的 `f73070 → f72606(autowake=0)` 也执行。区别于 Reset 的 relocation，墙回调不会把冰壶移回初始位置。后续滑行/训练入口在壶停用后结束，不能逐步派发回调的原生批量循环不会绕过这条路径。

调用原因及原始观察控制保留在[上一轮证据](case12000_wall_cleanup_cause_20261003.md)。本轮资源提取、原生指令核查和回归用于实现与验证，不改变先前观察的原始 Unity 数据。
