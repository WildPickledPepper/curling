# 11005：首处分叉与旧验收盲点

## 结论

之前确实沿着分叉点修过 12011、12008。遗漏在原始刚体姿态的读取与写回：`state() -> _pose() -> pyphysx.cast_transformation()` 会在读取时归一化四元数，因此日志中的四元数不能用于断言原始 PhysX 刚体已经逐位相同。角速度 setter 则直接读取 `get_global_pose()`，两条路径看到的值可能不同。

把已知发射位置、零竖直写入、精确投影和诊断用 A10 初始四元数全部对齐后，11005 的第一个原始姿态分叉发生在**第 4 次物理步的求解出口之后、下一次滑行写入之前**。首次受影响的是第 6 次角速度写入（包含发射 reset 写入）。

Unity 实际调用 `table[121708] -> wasm f72606`，执行 float32 四元数归一化并写回刚体；本地没有对应写回。已抓到该函数进入/退出时的原始内存变化，并与函数内的 `f32.sqrt/div/mul` 运算对应。

## 证据

- 重放 12 枪终点与历史记录全部一致；15,580 个摩擦随机值逐值一致。
- 第 4 步 `solverSetupSolve` 退出时 Unity 和本地原始四元数四分量完全相同。
- `f72606` 进入时仍为该值，退出时四分量变成下列归一化结果。
- 第 6 次 setter：本地 `state()` 报出的四元数恰好是 Unity 的写回结果，但本地刚体实际仍保存归一化前的值。这就是原有比较漏报的具体原因。

| 字段 | 求解器出口（两边相同） | Unity f72606 写回后 |
| --- | ---: | ---: |
| q.x | 6.440262012574749e-08 | 6.440261302032013e-08 |
| q.y | 0.2535548806190491 | 0.2535548508167267 |
| q.z | 1.688124839915872e-08 | 1.6881246622801882e-08 |
| q.w | 0.9673210978507996 | 0.96732097864151 |

归一化的 float32 平方模为 `1.000000238418579`，倒数模长为 `0.9999998807907104`；逐分量乘法完全复现写回值。此后 Transform 自己的归一化读取是另一个操作，不能与刚体写回合并。

第 6 次脚本输入在 float32 下相同，native wy 输出却为：本地 `0.00982974749058485`，Unity `0.009829753078520298`。

将 Unity 的真实输入交给现有投影函数仍得到正确结果，因此此前投影公式及浮点次序的修复没有被推翻；遗漏的是给它提供原始姿态的写回步骤。

## 已验证范围

诊断分支补上物理步后的姿态写回，前 487 次 native 角速度输出与 Unity 相同，下一次输出分叉移至第 488 次。但目标壶终点仍有 `35.604 mm` 误差（补写回前 `35.617 mm`）。这证明首处分叉已定位并被诊断消除，**不证明它独自解释了全部终点退化**。

当前主求解器默认还没有启用发射位置和零竖直写入；默认路径从发射就有先前已知差异。上述“首处分叉”明确指补齐已知条件后的第一个新分叉。A10 初始四元数来自历史记录，属于离线诊断输入。本轮未把诊断姿态写回加入主求解器。
