# 12009 第 313 步：余弦实现差异已定位

后续已[实施生产修复并通过完整回归](case12009_cos_repair_20261003.md)。本文及关联 JSON 保留修复前的直接观测事实和版本哈希。

原因是四元数积分调用了两种不同的 `cosf` 实现。相同半角输入 `0x3bd59dea`（`0.006519068963825703`）进入 Unity 与本地余弦函数，返回值分别是 `0x3f7ffe9c` 与 `0x3f7ffe9b`。这个 1 ULP 的差异精确解释本次第 313 步 `qy/qz/qw` 的分叉。

## 直接执行证据

Unity 原始 `f71259 / PxsDynamics.solverSetupSolve` 在第 313 步调用 `f71198 / integrateCore`，采样 setter ordinal 314。活动壶积分 call ID 87 的 bodyData 27 个字与 native 完全一致；唯一不同字是 byte offset 72 的 actor roster 整数索引，Unity 15、本地 14。线速度/角速度求解增量和 motion 增量共 12 个浮点字完全一致。时间步和旋转半角完全一致，正弦输入及返回值也逐字节相同。

Unity 实际调用链为 `f71198 → f33062 → f18889`。`f33062` 对该输入进入已反编译的小角度分支；`f18889` 按原始 WAT 运算顺序计算 double 多项式，最后执行 `f32.demote_f64`。call ID 89 记录的实际余弦返回值为 `0x3f7ffe9c`。

本地积分在 `_pyphysx.cp39-win_amd64.pyd` RVA `0x204d16` 调用余弦导入 thunk `0x450480`。导入表为 `api-ms-win-crt-math-l1-1-0.dll!cosf`，该次运行实际解析到 `C:\WINDOWS\System32\ucrtbase.dll` RVA `0xa77e0`。

指令级运行跟踪确认实际经过 UCRT 的以下分支，而非根据误差推断：

| UCRT RVA | 实际指令与计算 |
| --- | --- |
| `0xa7840` | `vmulsd`：将已提升到 double 的输入乘以 `0.5`。 |
| `0xa7848` | `vfnmadd213sd`：计算融合的 `1 − (x/2) × x`。 |
| `0xa7851` | `vcvtsd2ss`：将上述 double 结果舍入为 float32。 |
| `0xa7855` | 已观测到返回寄存器低 32 位为 `0x3f7ffe9b`。 |

此小角度分支只使用二次近似。Unity 此处实际执行的多项式包含更高次项及不同系数。这次输入恰好使两者落在相邻 float32 数值的舍入中点两侧：

| 数值 | 转为 float32 前的 double |
| --- | --- |
| Native 实际计算 | `0.9999787508699225` |
| 两个 float32 的舍入中点 | `0.9999787509441376` |
| 原始 Unity 余弦内核 | `0.9999787509452933` |

因此 native 向下舍入至 `0x3f7ffe9b`，Unity 向上舍入至 `0x3f7ffe9c`。此前样例通过只能说明它们的实际输入没有暴露这个返回值差异，不能证明两个余弦实现等价。

- 被动采样保留全部原始 Wasm 函数体。与未插桩的原始 Unity 对照，1276 组 setter/getter/pose、1275 个摩擦输入及最终协议结果一致。
- 本轮 Unity 新采样与此前基线的出手及 4000 个完成边界、两只冰壶状态共 **416104 字节完全一致**。
- Native 记录了 18 个真实指令边界，包含 UCRT 的实际分支。跟踪前后出手及 3000 步状态完全一致，无丢弃或未完成记录；运行时余弦函数的代码字节与记录版本的 UCRT 文件一致。
- 用实际 Unity 输入和实际 sin/cos 返回值执行**原始 `f71198` WAT**，精确复现其全部 112 字节 bodyData 输出。被动记录中间值前后计算输出不变。
