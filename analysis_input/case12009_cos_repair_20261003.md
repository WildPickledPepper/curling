# 12009 余弦分叉修复与完整回归

第 313 步已闭合。修复后 12009 从释放到第 4000 个完成边界，两只冰壶 P/Q/v/w 的 416104 字节全部一致，包含第 1275 步碰撞、停止和最终双方休眠。

修复依据是[此前直接观测的内部差异](case12009_cos_cause_20261003.md)：同一半角 `0x3bd59dea` 经 Unity `f33062 → f18889` 得到 `0x3f7ffe9c`，Windows UCRT `cosf` 二次近似得到 `0x3f7ffe9b`。生产代码现按原始 WAT 分支、常数、计算顺序及 double 到 float32 舍入移植余弦；没有姿态注入、采样结果查表或终点补偿。

## 生产调用与范围

`local_simulator/native_integrate_cos.py` 在 Unity 原生坐标场景的 Reset 之前安装一次。仅将 PhysX 的两处积分余弦调用重定向到随包的 `runtime/unity_integrate_cos.dll`，磁盘上的 pyphysx 和其他余弦调用保持原样。安装验证 native 文件 SHA256、原调用指令和新 DLL SHA256，失败即报错；远跳中继和 DLL 在进程内持续存活。

已静态核对的两处调用指令，在三个随包 ABI 中一致，地址不同：CP39 `0x1fc8fd/0x204d16`，CP38 `0x1f360d/0x1fba26`，CP313 `0x1fabdd/0x202ff6`。本次实际运行与全轨迹验收使用 Windows CP39；没有运行 CP38/CP313 全轨迹，不能将静态核对等同于运行验收。

对应原始 Unity `f71198` 的角速度模长上限为 `1e7`，本模拟器固定 `dt=0.01`，半角上限 50000。本移植实现 `f33062` 的直接分支、两个 double 核以及 `f18176` 的中等参数归约（绝对值位模式不超过 1305022426），完整覆盖此积分范围；不替换全局 `cosf`，不声称恢复任意大参数的 `f5976` 归约。超出所支持的有限输入范围返回 NaN，不回退到系统余弦。编译使用 SSE2、禁用快速数学、重结合和 FMA；构建脚本及 C 源码随包。更换编译产物需更新 DLL 哈希并重新验证。
